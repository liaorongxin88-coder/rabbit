# 生产流程人工表单完整度检查

来源：

- 飞书《Rabbit Batch 闭环与 UI 测试指南》：生产周期从配种、摸胎、备产、分娩、哺乳/带仔到断奶；失败分娩要求总仔数和活仔数为 0，断奶要求公母数之和等于断奶数和笼位容量。
- `doe-breeding-v2-design.md` §5.2：六大操作表单契约。

操作人、操作时间、母兔、批次、周期由登录态、路径和状态机周期锁确定，不作为重复输入字段。

| 动作 | 执行时必填 | 未执行/推迟 | 当前实现 |
| --- | --- | --- | --- |
| 催情 | 操作日期 | 下次提醒日期 | 批量催情使用当前日期；单只状态推进由服务端校验。 |
| 配种 | 操作日期、配种方式；体配需种公兔，人工授精可不选公兔 | 下次提醒日期 | 单只和批量表单均已支持日期、配种方式、公兔条件校验。 |
| 摸胎 | 操作日期、摸胎结论 | 下次提醒日期 | 怀孕/空怀/不确定已支持；不确定必须选择今天或未来复查日期。 |
| 备产 | 操作日期 | 下次提醒日期 | 已支持。 |
| 接产 | 操作日期、总产仔数、活仔数、留仔数；失败产三项必须为 0 | 下次提醒日期 | 已补齐留仔数；客户端和服务端均校验数量关系。 |
| 分笼/断奶 | 操作日期、断奶数量；公母数必须同时为 0 或相加等于断奶数；手工分配时需目标笼位 | 下次提醒日期 | 已有数量、性别、体重、自动/手工笼位；新增推迟分支。 |
| 流产 | 操作日期、死胎数、发生阶段由服务端自动取、照片文件引用 | 不支持推迟 | 已要求死胎数；照片选择和上传链路尚未接入，不能宣称该字段完成。 |
| 母兔离场 | 离场类型、离场日期、离场原因、不可撤销确认 | 不支持推迟 | 已支持淘汰/死亡、日期、原因和风险确认。 |
| 批次结束 | 结束日期；仍有活跃成员时强制结束确认和备注 | 不支持推迟 | 已支持。 |

## 已落地的契约保护

- V2 状态机拒绝缺少配种方式、接产三项数量、流产死胎数和断奶数量的请求。
- 接产校验 `0 <= keptKits <= liveKits <= totalKits`；失败产要求三项均为 0。
- 摸胎不确定、推迟动作必须使用今天或未来提醒日期；日历默认日期按兔场生产时长推导。
- Flutter 批次详情优先使用 `currentStage`，不再使用停止更新的 `currentStatus` 作为状态标签、筛选和搜索依据。
- 所有单只可推迟的生产表单已提供“本次未执行，改期提醒”分支，保持任务 PENDING。

3. Android 后台通知仍未迁移；当前“我的事件提醒”是用户+兔舍级的应用内提醒筛选和提前天数配置。
