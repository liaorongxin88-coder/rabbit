# 批量出库完整业务场景测试方案

## 1. 文档目的

本方案将飞书《养兔 App 批量出库 PRD》revision 12 转换为可重复执行的人工验收、Flutter 自动化、后端 API E2E 和数据库一致性检查。测试对象是当前主线实现，业务口径以 PRD 为准，当前实现边界以 `batch-outbound-implementation.md` 为准。

一条用例不能同时覆盖“出售”和“留种”等互斥结果。本方案使用一个固定的黄金兔舍作为基线，在冻结快照处分叉执行成功、冲突、权限撤回、断网和事务失败场景。用例设计优先确认业务交互是否符合养殖现场的人体工学，再验证状态和数据结果；不能用“最终数据正确”掩盖操作难以完成、容易误触或反馈难以理解的问题。只有所有 P0 分支都通过，才能认为核心出库链路具备发布条件。

不在本期范围：客户档案增强、NFC/扫码、蓝牙称重、导出、销售撤销或红冲。它们不得作为本期阻塞项，也不得混入核心出库断言。

## 2. 质量门禁

### 2.1 人体工学优先原则

测试人员应以“现场操作员站立持机、主要使用单手、另一只手可能正在进行养殖操作”为默认姿势执行核心流程，并至少用左手和右手各完成一轮。业务交互遵循以下前置原则：

1. 高频动作优先批量完成。正常兔的整笼、整排和整舍选择不得要求逐兔点选；只有提前出售、留种和异常处理进入逐兔操作。
2. 主操作位于拇指易达区。选择页和确认页的下一步/提交按钮固定在底部，滚动、筛选、展开抽屉和键盘弹出后仍可找到。
3. 主要触控目标至少 48 x 48 dp。相邻的选择、详情、删除和提交动作必须有清晰边界，不能依赖精准点按或只靠颜色识别。
4. 查看与修改分离。点击卡片主体查看详情，点击复选区域只改变选择；长按、双击、横滑和隐藏手势不能成为完成业务的必经路径。
5. 危险动作防误触。放弃草稿、留种和最终出库必须与普通浏览动作分离，并显示对象和影响数量；提交中禁止返回、重复点击或创建新任务。
6. 操作现场连续。查看档案、处理异常、切换筛选、App 前后台切换后，滚动位置、抽屉上下文、合法选择和表单不得丢失。
7. 反馈降低认知负担。状态同时使用图标、文字和数量；自动移出必须指出兔 ID 和原因；错误信息必须给出可执行的下一步。
8. 输入不遮挡任务。键盘弹出时当前字段、校验信息和下一操作保持可见；系统字体 200% 时允许布局降级为单列，但不能截断关键业务信息。

## 3. 黄金兔舍数据集

### 3.1 账号

| 账号 | 权限 | 用途 |
| --- | --- | --- |
| U-A | `control` | 主操作员，可正常出售、提前出售和留种 |
| U-B | `edit` | 可普通出库，不可提前出售或留种 |
| U-C | `view` | 只读验证，不得创建、保存或提交 |
| U-D | `control` | 并发操作员，用于换笼、隔离和抢先提交 |

每个账号使用独立登录会话。不得复用 token 来模拟权限变化。

### 3.2 空间与兔只

建立兔舍 `H-GOLDEN`，布局为 2 排 x 6 位 x 1 层，每笼 1 只。正常出售兔必须跨两个排、至少两个生产批次。

| 编号 | 位置 | 类型/阶段 | 并行状态 | 初始资格 | 默认选择 | 用途 |
| --- | --- | --- | --- | --- | --- | --- |
| G01 | 1-1-1 | 商品兔，出售日已到 | 无 | NORMAL | 是 | 正常出售，批次 B01 |
| G02 | 1-2-1 | 商品兔，出售日 +7 天 | 无 | EARLY_SALE | 否 | 提前出售，批次 B02 |
| G03 | 1-3-1 | 商品兔，出售日已到 | 隔离 | BLOCKED | 否 | 隔离优先级 |
| G04 | 1-4-1 | 商品兔，出售日已到 | OPEN 治疗 | BLOCKED | 否 | 治疗阻断 |
| G05 | 1-5-1 | 商品兔，出售日已到 | 未处理异常 | NEEDS_ACTION | 否 | 异常处理 |
| G07 | 1-6-1 | 种兔 | 无 | BLOCKED | 否 | 非商品兔 |
| G06 | 2-1-1 | 商品兔，出售日已到 | 无 | NORMAL | 是 | 正常出售，批次 B03 |
| G08 | 2-3-1 | 商品兔，无有效批次阶段 | 无 | BLOCKED | 否 | 阶段缺失 |
| G09 | 2-4-1 | 商品兔，出售日已到 | 笼位停用 | BLOCKED | 否 | 笼位阻断 |
| G10 | 2-5-1 | 商品兔，出售日已到 | 无 | NORMAL | 否 | 冻结后才创建 |
| G11 | 独立重置数据 | 商品兔，生长期 | 无 | EARLY_SALE | 否 | 留种分支，不能与 G02 共用结果 |
| G12 | 独立重置数据 | 商品兔，已出栏 | 不在场 | BLOCKED | 否 | 单兔入口历史态 |

黄金主流程创建 G01-G09 后首次预检的固定断言为：`normal=2`、`earlySale=1`、`needsAction=1`、`blocked=5`，默认选择仅包含 G01、G06。G10 只允许在冻结之后创建。

### 3.3 本地测试数据注入

手工执行数据脚本时只允许使用独立测试库 `rabbit_app_e2e`。Android runner 可以在确认本地 Flyway V11 后向开发库 `rabbit_app` 追加本轮数据，以便 Dev APK 经真实后端联调；不得指向共享测试库或生产库。脚本采用追加式隔离：每次生成四个账号、主兔舍和分支兔舍，并通过直接兔场成员关系授权，不删除已有数据；执行结果会打印本轮 `run_id`、账号、兔舍 ID、兔只 ID 和资格汇总。四个账号的测试密码统一为 `123456`。

```bash
docker exec -i rabbit-e2e-mysql \
  mysql -uroot -prabbit_root rabbit_app_e2e \
  < backend/src/test/resources/fixtures/batch_outbound_fixture.sql
```

主任务进入 `CONFIRMING`、冻结兔只快照后，才执行下面的脚本追加 G10。重复执行不会重复创建 G10。

```bash
docker exec -i rabbit-e2e-mysql \
  mysql -uroot -prabbit_root rabbit_app_e2e \
  < backend/src/test/resources/fixtures/batch_outbound_after_freeze.sql
```

不要在首次预检前运行 `batch_outbound_after_freeze.sql`，否则主场景的固定资格汇总会从 `2/1/1/5` 变为 `3/1/1/5`。

## 8. 数据库对账断言

每次成功提交必须按 `sale_order_id` 和冻结兔 ID 执行以下只读断言：

1. `sale_orders` 恰好 1 条，`request_id` 唯一。
2. `sale_order_items` 数量等于冻结兔数，且兔 ID 不重复。
3. 每条明细都有笼位、排、阶段、stateVersion、并行状态和 batch 快照。
4. 提前出售兔 `early_sale=true` 且原因、操作者可追踪；普通兔不得携带提前原因。
5. 出售兔 `rabbits.is_active=false`，未选、阻断和冻结后新增兔保持原状态。
6. 活跃 `batch_rabbits` 已退出；没有在场兔的批次变为已完成，其他批次保持进行中。
7. 每只出售兔恰好一条 `rabbit_departure_records` 和对应 `rabbit_status_history`。
8. 每个受影响笼位只按本次实际出栏数递减，不能为负。
9. `outbound_tasks`、`outbound_requests` 和销售单指向同一最终结果。
10. 重放相同 requestId 后以上计数全部不变。

冲突或事务失败时，上述业务表相对提交前必须零变化；只允许保留任务、幂等请求和错误快照等审计数据。

## 9. 人工测试记录模板

每轮人工验收至少记录：App 版本/commit、后端版本、数据库 migration、设备型号、Android 版本、账号权限、兔舍 fixture 版本、网络条件、操作者惯用手、持机姿势、是否开启大字体/TalkBack、requestId、taskId、saleOrderId、步骤结果、截图/录屏、误触次数、重复输入次数、失败日志和清理结果。

建议结果值只使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`。`BLOCKED` 必须写明外部依赖；不能把未执行项记为通过。

## 10. 当前发布风险

当前实现已经具备专用出库 list/query/edit 权限，并对提前出售继续校验兔场 `control` 能力；功能开关、产品埋点、独立审计事件流、自动对账、大兔舍分页/虚拟化以及可靠 outbox 仍未完成。因此现阶段可以用本方案验收核心原子出库链路，但不能据此宣称 PRD 的全部上线检查项已经完成。灰度发布前至少还需要：功能开关、可查询的对账结果、关键指标与告警、1000 只规模基线、最低 Android 版本，以及 ERG-01 至 ERG-10 的真机人体工学证据。
