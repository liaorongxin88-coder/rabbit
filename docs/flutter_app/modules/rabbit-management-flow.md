# Flutter 兔场管理流程

当前 Flutter 客户端采用多级兔场管理流程：

```text
兔场列表 -> 兔场详情 -> 笼位管理 / 兔只管理 / 生产批次
生产批次 -> Batch 详情 -> 批量催情 / 批量配种 / 单兔生产任务 -> 断奶 -> 出库 / 母兔离场 -> Batch 结束
```

## 路由

- `/houses`
- `/houses/:houseId`
- `/houses/:houseId/cages`
- `/houses/:houseId/rabbits`
- `/houses/:houseId/batches`
- `/houses/:houseId/batches/:batchId`

## Batch 详情与现场操作

Batch 列表以兔舍为边界加载全部 Batch，支持批次号/备注搜索和状态筛选；点击卡片进入详情，不把批次操作藏在兔舍概览里。详情页按“先汇总、再筛选、后成员”的顺序展示：

- 顶部显示 Batch 状态、日期、活跃成员和结束入口；结束前若仍有活跃成员，必须明确勾选强制结束。
- 统计区区分全部成员、活跃成员、繁殖母兔、商品兔、当前带仔和已退出成员。
- 成员列表支持兔号/笼号/状态/事件搜索、角色筛选、生产状态筛选和在场范围筛选；使用 `ListView.builder`，可承载千级成员。
- 有 `control` 权限时，可从当前筛选结果批量开始/完成催情；切换筛选或刷新会清除不可见/已失效选择，网络失败重试复用同一个 `requestId`。
- 有编辑权限时，可从当前筛选结果选择最多 1000 只“待配种”或“哺乳中”的母兔，统一选择种公兔和配种日期后整批提交。服务端先完整校验再写入，任何一只不符合条件都会使整批回滚；完全相同的失败草稿复用稳定 `requestId`，公兔、日期或母兔集合变化后自动换新 ID。
- 活跃繁殖母兔提供“母兔离场”入口，可选择淘汰或死亡、填写日期/原因/备注，并在确认不可撤销后调用统一离场事件；服务端会关闭该母兔的开放周期和活跃 Batch 关系。
- 只读权限仍可查看完整成员和生产状态，但不显示写操作；生产表单完成后会刷新 Batch 详情和首页任务队列。
- 生产表单和离场表单完成后会刷新 Batch 详情、兔只/笼位列表和首页任务队列；写请求在同一表单草稿内复用 `requestId`，失败可安全重试。

离场表单目前限定在 Batch 详情的活跃繁殖母兔上下文；兔只总表的独立或批量离场仍需另行设计入口，不能把这条 Batch UI 证据外推到所有兔只操作。

## 大型兔舍与权限边界

- 创建 Batch、兔只列表和 Batch 成员列表均使用分页或惰性构建，不在首帧创建千级复选框/列表项。
- 出库选择页按排/笼使用 Sliver 惰性构建；确认页每次展开 20 个笼位，单笼只展示前 4 个兔号和剩余数量，避免 7000 只商品兔形成超长 widget 树或字符串。
- 出库深链在创建任务前校验兔舍权限。只读账号只看到明确的只读状态和返回操作，不会初始化、取消或提交出库任务。
- 统计卡、笼位卡、重置密码弹窗和长标题对 360x800、412x915 与 200% 字号提供稳定尺寸或截断；NFC、出库失败和权限请求均保留明确的重试入口。

## 新增兔只

新增兔只必须从具体笼位进入：

```text
兔场详情 -> 笼位管理 -> 选择具体笼位 -> 录入兔只
```

不要在兔只列表页新增全局无上下文的“新增兔只”入口。兔只列表页主要用于查看和编辑已有兔只。

## 主题和交互

- 正常兔只交互使用主蓝、田野绿和辅助 amber。
- 红色只用于错误或破坏性状态。
- 视觉 token 放在 `app/lib/src/ui/core/themes/app_theme.dart`。
- 长兔场名、用户名和事件名称必须做省略或换行约束，不能撑破移动端布局。
