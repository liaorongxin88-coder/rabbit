## 3. 尚未闭环的 4 条 BUG

### BUG-01 商品兔新增操作的日期描述不正确

- 来源：`recvtK50BknqVL`
- Base 状态：方案设计中，P0，无负责人，无完成时间。
- 问题：商品兔“入场日期”实际表示断奶日期。成长阶段应由断奶日期和兔舍阶段配置自动计算，不应由用户手工填写。
- 处理设计：页面统一显示“断奶日期”；删除成长阶段输入；服务端根据断奶日期和兔舍配置计算当前阶段及阶段进入日期。修改兔舍配置后是否追溯历史记录需单独确认。
- 验收：覆盖每个阶段边界的前一天、当天和后一天；页面文案、保存值、详情值和任务提醒一致；用户不能提交手工成长阶段。
- 完成条件：补负责人、目标版本、日期计算规则、配置变更策略、修复提交及自动化测试。

### BUG-02 商品兔首页日程提醒没有确认接口

- 来源：`recvtK5orv3zds`
- Base 状态：方案设计中，P0，无负责人，无完成时间。
- 问题：日常观察任务没有完成接口，记录中的 2026-08-31 验收反馈为“预期操作没法通过”。
- 处理设计：服务端提供可审计、幂等的任务完成能力。若采用“完成投喂即完成观察”的方案，必须明确投喂记录与观察任务的一对一或一对多关系，不能只在客户端隐藏任务。
- 验收：完成投喂或确认操作后，任务状态变为完成，首页、笼位和兔卡查询结果一致；同一 `requestId` 重复提交只生效一次；失败后保留操作上下文并显示原因。
- 完成条件：确认业务方案、接口契约、幂等键、负责人、目标版本和端到端验收证据。

### BUG-03 操作后的默认提醒日期未使用兔舍周期

- 来源：`recvtKb2GNRLjA`
- Base 状态：方案设计中，P1，无负责人，无完成时间。
- 问题：催情、配种、摸胎、接产后的部分提醒仍使用全局默认时长，页面还出现旧的“备产提前天数”描述。
- 处理设计：所有生产操作只读取操作所属兔舍的周期配置；保存操作时固化本次计算依据和结果；后续配置修改不静默改写历史提醒，除非执行带审计的重算。
- 验收：兔舍配置设置为与全局默认值不同的数值，逐一执行催情、配种、摸胎、备产、接产，核对提醒日期和来源配置；页面不得再出现已废弃参数。
- 完成条件：补齐五类操作的参数映射表、配置快照规则、负责人、目标版本及跨端复测证据。

### BUG-04 首页任务筛选不够简洁

- 来源：`recvtKj6krTSCm`
- Base 状态：方案设计中，P0，无负责人，无完成时间。
- 问题：批次下拉已经实现，兔舍下拉尚未实现，2026-08-31 验收未通过。
- 处理设计：任务列表使用“兔舍 -> 批次”的级联筛选。切换兔舍时清理不属于该兔舍的批次选择；筛选值反映在请求参数中；清空筛选恢复全部有权查看的任务。
- 验收：兔舍和批次候选动态加载；切换兔舍后候选项和任务列表同步收敛；无数据、加载失败和无权限三种状态可区分；窄屏和 200% 字号下控件可用。
- 完成条件：补负责人、权限范围、默认筛选策略、目标版本、浏览器与真机证据。

## 6. BUG 记录闭环模板

在不调整 Base 字段结构的前提下，可先统一把以下内容写入“需求详细描述”字段：

```text
环境：版本、设备/浏览器、兔舍、账号角色
前置条件：必要数据和状态
复现步骤：编号步骤
实际结果：可观察事实
期望结果：唯一、可验证的结果
影响范围：角色、页面、数据、频率
修复说明：根因、提交、迁移、接口或页面变化
验收步骤：正常、失败、边界、重复提交
通过标准：界面结果 + 数据查询结果
验收证据：测试报告、截图目录、日志或查询
```

所有交互类 BUG 还需满足[交互验收规范](interaction-acceptance-spec.md)：失败可见、失败不丢输入、重复提交只生效一次、批量操作说明范围和结果、边界提示明确、断网可恢复、360x800 与 200% 字号可用。
