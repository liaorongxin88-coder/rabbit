## 2. 业务目标与页面

用户需要在批次执行中查看生产进度，在批次结束后复盘繁殖、断奶、出栏、销售和饲料效率。

建议页面结构：

1. 批次详情新增“统计”页签，批次是固定上下文。
2. 数据看板复用同一统计接口，必须选择批次后才展示批次指标。
3. 页面顶部显示兔舍、批次编号、批次状态、统计更新时间和数据完整性。
4. 指标按“繁殖、产崽与选留、断奶与出栏、销售与饲料”分组。
5. 进行中批次展示实时累计，已完成批次默认只读；带审计的更正可以触发重算。

## 3. Base 已明确的指标

Base 主记录明确了下列符号和公式：

`M` 配种母兔数，`G` 参与配种公兔数，`P` 确认怀孕母兔数，`A` 流产母兔数，`D` 完成接产母兔数，`B` 产崽总数，`L` 活崽总数，`K` 留崽数大于 0 的窝数，`S` 选留总数，`W` 断奶数量，`IW` 入笼总重量，`O` 出栏数量，`OW` 出栏总重，`R` 总销售金额，`MF` 母兔阶段饲料量，`GF` 育肥阶段商品兔饲料量。

| 分组 | 指标 | Base 公式或定义 |
| --- | --- | --- |
| 配种 | 配种日期 | 母兔配种操作时间 |
| 配种 | 受胎数量 | `M` |

| 接产 | 平均窝产数 | `B / D` |
| 接产 | 活崽总数 | `SUM(每次接产的活崽数)` |
| 接产 | 平均活崽率 | `L / B` |
| 选留 | 选留窝数 | `COUNT(留崽数 != 0)` |
| 选留 | 选留总数 | `SUM(留崽数)` |
| 选留 | 选留活崽率 | `S / L` |

| 断奶 | 断奶数量 | `SUM(断奶崽数)` |

| 饲料 | 育肥期料肉比 | `GF / OW` |

## 4. 统计口径审阅决策

### D-STAT-01 计数粒度

Base 的“母兔数”无法区分兔只去重数和繁殖次数。建议同时提供两个口径：

- `配种母兔数`：批次内至少有一次已确认配种的去重母兔数，仅用于规模展示。
- `配种母兔次`：按繁殖周期去重的已确认配种次数，用作受胎率、怀孕数和流产率的分母或分子。

- [ ] 采用上述双指标方案，比例按繁殖周期计算（推荐）。
- [ ] 所有指标按母兔去重计算。
- [ ] 其他：____________________。

### D-STAT-02 育肥期料肉比

主需求公式为 `GF / OW`，附件样表公式为 `GF / (OW - IW)`，两者分别表示出栏重量口径和增重口径。

- [ ] 主指标采用附件的增重口径 `GF / (OW - IW)`，另显示 `GF / OW` 为“商品料肉比”（推荐）。
- [ ] 只采用主需求公式 `GF / OW`。
- [ ] 其他：____________________。

任何分母小于或等于 0 的情况都返回空值和原因，不返回 0、无穷大或 `NaN`。

### D-STAT-03 批次归属

- [ ] 每条配种、生产、断奶、入笼、出售和饲料记录保存不可变的 `batch_id` 或繁殖周期 ID（推荐）。
- [ ] 允许从兔只当前批次反查历史归属。

推荐第一项。当前批次反查会在兔只转批次、退出或重新加入后污染历史统计。跨批次销售必须在销售明细中按批次保存数量、重量和金额，不能只保存在销售单头部。

### D-STAT-04 事件状态与更正

- [ ] 只统计已确认、未撤销、未冲正的业务事件（推荐）。
- [ ] 草稿或取消记录也进入统计。

补录、撤销、退货和数量更正后实时重算。已完成批次允许有权限的用户发起带原因和审计记录的更正，页面显示最后更新时间及数据已更正标识。

### D-STAT-05 饲料分摊

推荐规则：饲料记录优先直接关联批次和阶段。无法直接关联且同一笼位混有多个批次时，该条记录不进入料肉比，页面标记“饲料归属不完整”，不按兔只数量静默估算。

- [ ] 采用直接归属，不完整时不计算（推荐）。
- [ ] 混批笼位按投喂时点的在栏兔只数分摊。
- [ ] 其他：____________________。

### D-STAT-06 权限与端范围

- [ ] 生产数量和比率沿用批次查看权限；销售金额、单价和成本另受销售或财务查看权限控制（推荐）。
- [ ] 所有批次查看者都能看到销售金额和成本。

移动端首期建议展示生产指标和只读销售摘要；完整财务与饲料分析先放在 Admin。

## 5. 统一计算规则

审阅通过后，所有指标遵守以下规则：

1. 以批次 ID 和兔舍 ID 为基本隔离条件。
2. 比例按原始值计算，展示层四舍五入到 2 位小数。
3. 数量使用整数，重量和金额使用十进制定点数，禁止二进制浮点累计。
4. 分母为 0 或数据归属不完整时返回 `null`，同时返回 `unavailableReason`。
5. 页面区分“真实为 0”“尚无记录”“数据不完整”和“加载失败”。
6. 同一 `requestId` 的重复业务事件只统计一次。
7. 接产、留崽和断奶取有效事件的最终值，不把每次修改历史重复相加。
8. 销售退回和冲正从对应批次的数量、重量和金额中扣减，并保留审计记录。
9. 已完成批次不固化为不可更正快照，但每次更正都要更新统计版本和时间。

## 6. 当前代码差异

当前 `GET /api/batches/{batchId}/statistics` 只返回 4 项：`totalLitters`、`totalKits`、`totalLiveKits`、`totalWeaned`。实现位于 [BatchStatisticsMapper.xml](../../backend/rabbit-production/src/main/resources/mapper/modules/batch/BatchStatisticsMapper.xml)。

| 差异 | 当前行为 | 目标行为 |
| --- | --- | --- |
| 指标范围 | 只有产崽窝数、产崽总数、活崽总数、断奶数量 | 增加 Base 明确的比例、出栏、销售和饲料指标 |
| 记录边界 | 按兔舍和批次累计，不筛事件状态、日期或撤销 | 只统计有效最终事件，支持更正和冲正 |
| 时间 | 实时累计，不使用批次起止时间 | 以不可变批次归属和事件时间为准 |
| 成员数 | Admin 包含已退出关系，Flutter 只算活跃关系 | 明确“历史成员”和“当前活跃成员”两个指标 |
| 未结束周期 | Admin 使用“不是 CLOSED”，空值也会计入 | 统一使用服务端 `OPEN` 判据 |
| 历史批次 | Admin 当前统计入口只列进行中批次 | 批次详情可查看进行中和已完成批次 |
| 重入 | 退出后重入会产生多行关系，客户端按行计数 | 服务端按业务定义去重并分别返回历史关系数与兔只数 |

建议扩展现有统计接口，保留 4 个旧字段兼容 Admin 和 Flutter，同时新增分组对象 `breeding`、`delivery`、`weaning`、`outbound`、`sales`、`feed` 和 `dataQuality`。所有字段应来自一次服务端聚合，避免多个请求产生不同更新时间。

## 9. 按钮设计规则

### D-BTN-01 文案与图标

- [ ] 业务动作使用文字按钮或“图标 + 文字”；状态标识可以使用图标，但必须同时显示中文标签（推荐）。
- [ ] 所有按钮一律只使用文字。

熟悉的关闭、刷新、上一页等工具图标可以仅显示图标，但必须有可访问名称和悬停提示。此规则解决主记录“不要用图标”和笼位图“图标加中文标签”的冲突。

### D-BTN-02 权限和不可用状态

1. 无权知道该能力存在的角色不显示按钮。
2. 有查看权但当前状态不允许操作时显示禁用按钮，并在邻近位置或 tooltip 说明原因。
3. 前端显隐不能代替服务端权限校验。
4. 页面、按钮和后端接口必须使用同一个权限语义。

- [ ] 采用上述规则（推荐）。
- [ ] 无权限时统一显示禁用按钮。

### D-BTN-03 提交与反馈

所有写操作遵守：

- 点击后按钮进入加载态并禁用，防止连续点击。
- 服务端使用 `requestId` 或业务幂等键保证只生效一次。
- 失败信息显示在当前操作区域，表单不关闭、输入不丢失。
- 成功后刷新受影响数据，并说明结果和跳过项。
- 删除、出售、离场、强制完成和批量操作需要二次确认，确认页显示影响数量。

### D-BTN-04 返回按钮

- 显示“返回”文字或箭头加“返回”。
- 正常返回不修改业务状态。
- 存在未保存输入时二次确认。
- 没有浏览器历史时返回模块列表页，不退出工作台或跳到登录页。

- [ ] 采用上述统一返回规则（推荐）。
- [ ] 各页面单独定义返回目标。

### D-BTN-05 异常记录入口

Base 中存在冲突：旧记录 `recvt7VzBVO50v` 把入口放在兔子详情，新记录 `recvtK8O92WfgQ` 倾向移到笼位页。

- [ ] 笼位页作为主入口，先选笼位内兔只；兔子详情保留快捷入口（推荐）。
- [ ] 只保留笼位页入口。
- [ ] 只保留兔子详情入口。

提交后生成异常记录并刷新当前页面；失败保留图片、说明和兔只选择；重复提交只生成一条记录。

## 11. 当前代码需要对齐的事项

代码基线主要在 [workspace-production-page.tsx](../../admin/src/pages/workspace-production-page.tsx) 和 [workspace-outbound-dialog.tsx](../../admin/src/components/workspace-outbound-dialog.tsx)。需求关闭前需处理或明确接受以下差异：

1. “自动匹配当前业务周期”实际会清空周期 ID，而提交逻辑拒绝空周期，文案与动作相反。
2. 除流产外，生产操作菜单没有按所选周期阶段过滤，用户可以选择后端必定拒绝的动作。
3. “强制退出仍在批次中的兔只”不能越过未结束周期或待分笼记录，页面没有提前说明。
4. 新建按钮按批次编辑权限控制，后端新建接口要求批次新增权限，语义不一致。
5. Dashboard 的“前往出库”没有先检查出库权限。
6. Admin 没有批次详情、添加成员和移除成员入口，批次维护不能在 Admin 闭环。
7. 创建批次只添加批次标签，不启动繁殖周期，但 Flutter 生命周期测试仍断言“建批即入轨”。
8. 权限不足的按钮普遍只禁用，没有 tooltip 或邻近原因说明。
9. 批次列表加载失败后显示“还没有生产批次”，网络失败和真实空数据混淆。
10. “失败分娩（流产）”与独立“记录流产”并存，适用阶段和结果不同，但文案没有解释。

## 12. 按钮验收标准

每个页面建立按钮矩阵，至少记录：按钮文案、角色、可见条件、启用条件、点击动作、状态变化、确认文案、成功反馈、失败反馈、幂等键和验收证据。

统一通过标准：

1. 用户只看文案即可判断用途和影响对象。
2. 无权限操作无法通过前端或直接调用接口执行。
3. 禁用按钮说明具体原因，不能只变灰。
4. 危险和批量操作在提交前显示影响范围。
5. 成功后页面数据和服务端数据一致；失败后输入保留且原因可见。
6. 连续点击三次只产生一次业务结果。
7. 360x800、200% 字号和桌面宽度下无截断、遮挡或不可点击区域。
