# 系统演进说明

本文记录 Rabbit 走到当前形态的关键转折：哪些模型被推翻过、为什么推翻、
以及现在的结论建立在什么前提上。它解释「为什么是这样」，不描述「现在是什么」——
当前状态见 [architecture.md](architecture.md) 和各子项目文档。

演进证据以 `backend/rabbit-boot/src/main/resources/db/migration/` 下的 Flyway 迁移为主线。
迁移文件本身带有决策注释，遇到冲突以迁移和当前源码为准。

## 一、账号模型：从商户到直接成员

最初的设计在账号和兔场之间放了一层「商户」：`sys_user` 和 `rabbit_houses` 都挂 `merchant_id`。
这一层经历了完整的引入、简化、替换和拆除：

| 迁移 | 动作 |
| --- | --- |
| V10 | 简化商户账号 |
| V14 | 改为商户—兔场访问模型 |
| V15 | 引入 `house_users` 直接成员关系 |
| V16 | 删除 `merchant_id` 及其外键与索引 |

**结论：全局账号通过 `house_users` 直接加入一个或多个兔场，没有中间组织层。**
兔场隔离由 `X-House-Id` 加服务端权限校验实现，共同 `OWNER` 是允许的形态，
零兔场账号是合法状态。这一轮的教训是：在租户边界还没被真实业务压过之前，
多加一层归属只会让权限查询和数据隔离同时变复杂。

## 二、认证：从密码到手机号

| 迁移 | 动作 |
| --- | --- |
| V13 | 手机号短信登录 |
| V17 | 一键取号尝试记录 |
| V18 | 取号租约与限流桶 |
| V19 | 验证码从数据库移入缓存 |

手机号以服务端 HMAC 后的 `phone_hash` 作为唯一查找键，客户端和日志都不接触密钥。
验证码搬进缓存是因为它天然带过期语义，放在数据库里既要自己清理又要额外索引。

微信登录当前只以 `sys_user.openid` 兼容稳定身份，`bindingToken`、强制绑定手机号
和账号合并尚未实现。接口契约见 [手机号认证与后续适配](../backend/modules/auth-phone-wechat.md)。

## 三、母兔生产流程：V2 重写

这是改动最深的一次。旧模型把母兔的生产状态摊在兔只行上，无法表达同一只母兔
同时处于两个周期（血配：哺乳中的母兔重新配种）。

| 迁移 | 动作 |
| --- | --- |
| V21 | 允许重叠生产周期 |
| V22 | 生产周期编号按批次划分 |
| V25 | 兔只阶段与配种笼守卫 |
| V26 | V2 结构纯加法引入 `repro_events` / `breeding_cycles` / `litters` |
| V27 | 存量回填（一次性停写窗口） |
| V28 | 删除兼容列，旧写路径退出 |
| V29 | `weaning_records.batch_id` 放开为可空，支持散养母兔分笼 |

采用「加法迁移 → 回填 → 删兼容」三步而不是原地改表，是为了让新旧写路径共存一段时间，
切换点只有一个。这条路径值得复用。

### 旧写路径删除后暴露的静默错误

切换后出现的四个缺陷有同一个根因：仍有代码在读只有旧路径才维护的列。
它们都不报错，只是结果不对。

| 缺陷 | 影响 |
| --- | --- |
| 建批次不开生产周期 | 母兔无阶段、无待办，生产流程从界面无法开始 |
| 兔只离场不结周期 | 周期永远 OPEN，占着唯一键，待办永久 PENDING |
| 种公兔未落库 | 仔兔 `father_id` 为空，谱系永久丢失 |
| 仪表盘指标失真 | 「已配种」把刚入轨的母兔也算进去，「在哺仔兔」恒为 0 |

并行周期专项验收又跑出三个，根因不同——不是读了旧列，而是**新模型允许的形状
超出了旧约束的假设**：一兔只有一条周期、每条周期必属一个批次。

**放宽一处约束时，要把依赖这条约束的地方一并走一遍。**

### 批次归属：一条被推翻又重建的约束

V27 当时刻意不建「母兔在批次内周期唯一」的约束，理由是它会挡掉特意放行的血配。
V44 换了个解法推翻这个裁定：血配的第二条周期不再被禁止，而是**必须落到另一个批次**。
「母兔同时在两个周期」与「母兔同时在两个批次」于是变成同一件事，
批次才真正成为需求里说的「一组繁殖母兔的生产管理容器」。

第二个周期的批次归属**要求调用方显式传入，服务端不自动建批**。自动造的批次会带着
用户没取过的编号出现在列表里，还得用户亲手结束，与「批次由人员主动点击结束」直接冲突；
且自动建批只覆盖「新建一个」，剥夺了「放进现有批次」这个更常见的选择。
代价是血配时多一次选批次交互，而那正是需要用户决策的地方。

迁移里的「恢复批次」编号只用于存量数据收敛，不是运行时行为。

状态机与数据结构见 [母兔生产流程 V2](../features/reproduction-v2/design.md)。

## 四、操作追踪：两套割裂机制的合并

`audit_logs` 知道谁调了哪个接口但不知道改了哪只兔，业务表的 `create_by` 一半存数字 ID
一半存展示名，跨表归因直接算错。V48 到 V52 把两者收口到一条通用事件流上：

| 迁移 | 动作 |
| --- | --- |
| V48 | 规范审计操作人 |
| V49 | `audit_logs` 增加操作坐标 |
| V50 | 兔笼快照 |
| V51 | 泛化 `repro_events` 为通用操作事件流 |
| V52 | 回填兔只与投喂的操作人名 |

`repro_events` 之所以被选中泛化而不是新建表，是因为它已经是全仓唯一设计正确的追加流：
追加写、唯一键幂等、JSON 载荷、操作人快照。

设计、切面顺序约束和读接口契约见 [操作追踪与事务边界](../backend/modules/operation-tracking.md)。

## 五、商品兔成长阶段的收敛

| 迁移 | 动作 |
| --- | --- |
| V34 | 成长阶段与兔只任务 |
| V41 | 规范商品兔成长阶段 |
| V53 | 用 CHECK 约束把 `growth_stage` 限定为商品兔专用 |

后备兔和种兔一度也写 `growth_stage`，语义与商品兔的生长管线并不相同。
V53 清空非商品兔的该列并加约束，把「成长阶段」彻底还给商品兔，
后备与种兔改由 `replacement_records` 和生产周期表达。

## 六、后端模块化

后端从单个 Maven 工程拆成 `rabbit-platform` / `rabbit-access` / `rabbit-production` /
`rabbit-reporting` / `rabbit-boot` 五个模块，仍然只产出一个进程和一个镜像。
背景、依赖方向和未采用的方案见 [ADR 0002](../adr/0002-backend-maven-modules.md)。

配套的一条约定是**单元测试下沉到所属模块**，`rabbit-boot` 只保留真正需要全模块类路径的测试
（ArchUnit 规则、控制器权限扫描、schema SQL 检查）和需要完整应用上下文的 `*IT.java`。
`BootTestPlacementTest` 强制这条规则。这样内环可以用 `mvn -pl <模块> -am test`
只跑改动模块，不必每次全量构建。

## 七、几条留下来的工程结论

- **不报错的错误最贵。** V2 切换和并行周期两轮暴露的七个缺陷全部是静默错误：
  流程照常返回，数据悄悄不对。凡是删除旧写路径或放宽旧约束，都要主动去找谁还依赖它。
- **同类自调用不能只靠 grep 排查。** 文本扫描会把同名重载调用当成递归跳过，
  字节码规则不会。详见 [操作追踪与事务边界](../backend/modules/operation-tracking.md)。
- **并发在验证阶段是负收益。** 多条工作流同时跑 e2e 时，单次耗时从 15 分钟涨到 30 分钟；
  只剩一个验证进程立刻回落。并发的收益在写代码阶段，验证要错峰。
  并发跑 e2e 时每条流用独立的 `E2E_SCHEMA_SUFFIX`。
- **发布的每一层都要各自的证据。** 质量门禁、制品构建、远端容器切换、数据库迁移、
  公开探测和客户端安装是六件事，任何一层成功都不能替代其它层。见 [ADR 0001](../adr/0001-ci-cd-and-service-delivery.md)。
