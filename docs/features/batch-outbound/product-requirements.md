# 1. 需求概述

## 1.1 背景与问题

兔场出货通常以整舍、整排或整笼为现场操作单位，但系统最终必须准确记录到具体兔只。现有能力偏向单只处理，面对集中出货时需要反复进入兔只或笼位操作，效率较低，也容易出现范围理解错误、不可售兔被误选、提前出售无原因、多人操作产生状态冲突以及重复提交形成重复销售单等问题。

本需求建设统一的“出库任务”，将空间范围展开为明确的兔只清单，并以状态机和并行阻断状态判断资格。用户可以快速批量选择正常可出售兔，也可下钻到笼位和兔只处理提前出售、留种和异常；最终由服务端在同一事务中完成销售单、兔只状态、生产批次和笼位数据更新。

## 1.2 产品目标

**效率目标。**支持从单兔、单笼、整排和整舍入口发起同一套出库流程，显著减少集中出货时的重复操作。

**准确目标。**位置只作为候选范围，最终提交对象必须是冻结后的兔只 ID 清单；不可出库对象不能因批量选择被带入。

**完整目标。**正常出售、提前出售、留种、状态冲突、弱网恢复和销售结果形成可追溯闭环。

**一致性目标。**一次出库全部成功或全部回滚，重复点击或网络重试不得生成重复销售单。

## 1.3 成功指标

| 指标 | 定义 | 首版目标 |
|-|-|-|
| 出库任务完成率 | 成功提交任务数 / 创建任务数，排除用户主动取消 | 上线后观察并建立基线，稳定期不低于 95% |
| 批量能力使用率 | 按排或整舍发起的成功任务 / 全部成功任务 | 上线后观察，验证批量能力真实使用 |
| 状态冲突率 | 最终预检返回冲突的任务 / 发起提交任务 | 持续监控并按原因分类下降 |
| 重复销售单率 | 同一业务操作产生重复销售单的比例 | 0 |
| 数据一致性异常 | 销售单、兔只、批次、笼位任一不一致的任务数 | 0 |
| 任务耗时 | 从进入选择页到提交成功的时间 | 按范围分层统计，首版建立基线 |

## 1.4 约束与假设

首版运行于 Android 移动端，主要用于兔场现场操作。系统已有兔舍、笼位、兔只、生产批次、销售单和用户权限基础能力，但商品兔阶段、稳定空间坐标、统一预检和原子提交可能需要补齐。最终开发前需确认现网模型与本需求的字段映射。

# 2. 需求范围

## 2.1 本期范围

- 单兔、单笼、整排、整舍四类入口创建统一出库任务。
- 按排、按笼和整舍浏览与批量选择正常可出售兔。
- 逐兔纳入、移出、提前出售、标记留种和查看档案。
- 状态摘要、异常筛选、选择快照、确认表单和分组清单。
- 提交前最终预检、状态冲突处理、幂等提交和原子事务。
- 出库成功结果、销售单查看、草稿恢复和弱网反馈。
- 销售单、兔只、批次、笼位、提醒、报表的同步更新。
- 权限校验、关键操作日志、业务审计和产品埋点。

## 2.2 非本期范围

- 完整客户档案与应收账款管理；首版客户可使用历史选择或文本输入。
- 运输车辆调度、物流轨迹和电子合同。
- 离线最终出库；离线状态仅允许保存和查看草稿。
- 蓝牙称重、NFC、扫码硬件接入，可作为后续增强项。
- 销售单审批流、财务结算和发票能力。
- 已完成出库单的直接反向编辑；如需撤销，应另行定义退回或冲销流程。

# 3. 用户、角色与权限

| 角色 | 典型职责 | 权限要求 |
|-|-|-|
| 兔场操作员 | 现场选择兔只、填写重量和销售资料、提交出库 | 目标兔舍 view + edit；具备出库创建和提交权限 |
| 兔场管理员 | 处理提前出售、留种、异常和任务冲突 | 操作员权限及对应业务状态迁移权限 |
| 只读用户 | 查看销售单、兔只历史和出库结果 | view；不可创建、编辑或提交任务 |
| 系统服务 | 最终校验、事务更新、幂等和审计 | 服务内部权限，不允许绕过业务规则 |

能够管理笼位不等于能够绕过状态机。提前出售和留种属于独立业务动作，需分别校验权限并记录操作人、时间、提交前状态和原因。权限在进入任务、执行特殊操作和最终提交时均需校验，不能只由客户端控制按钮显示。

# 4. 业务对象与核心口径

## 4.1 统一出库任务

单兔、单笼、整排和整舍不建设四套独立流程。所有入口创建同一种出库任务，入口仅决定初始范围和默认展示方式。任务至少包含任务 ID、兔场与兔舍、入口类型、原始范围、当前兔只选择、资格快照、销售字段、操作人、创建时间、更新时间和任务状态。

## 4.2 位置与提交对象

兔舍、排和笼位只用于展开候选范围。系统真正提交、审计和生成销售明细的对象必须是明确的兔只 ID。进入确认页时冻结兔只 ID 与状态版本，之后新进入该范围的兔只不会自动加入；已离开或状态变化的兔只由最终预检识别。

## 4.3 任务状态

| 状态 | 说明 | 允许动作 |
|-|-|-|
| 选择中 | 范围已展开，用户正在调整兔只 | 选择、筛选、逐兔处理、保存草稿、取消 |
| 待确认 | 兔只快照已形成，正在填写和核对销售资料 | 编辑表单、返回修改、提交、取消 |
| 提交中 | 请求已发送，正在确认服务端结果 | 查询状态；禁止重复提交和破坏性返回 |
| 已完成 | 销售单与状态更新成功 | 查看销售单和结果；不可再次提交 |
| 已取消 | 用户明确放弃草稿 | 只读审计或清理；不可恢复提交 |

# 5. 状态机与出库资格

## 5.1 资格分类

位置范围展开后，每只兔统一归类为“正常可出库、可提前出售、需人工处理、禁止出库”。分类结果必须包含业务代码与用户可理解的原因文案。

| 当前状态 | 默认行为 | 允许操作 | 提交结果 |
|-|-|-|-|
| 商品_可出售 | 批量操作可默认选中 | 纳入或移出本次出库 | 商品_出栏 |
| 商品_适应期 | 不自动选择 | 按权限逐兔提前出售并填写原因 | 商品_出栏，记录提前出售 |
| 商品_生长期 | 不自动选择 | 提前出售或标记留种 | 商品_出栏或进入后备管理 |
| 商品_育肥期 | 不自动选择 | 提前出售或标记留种 | 商品_出栏或进入后备管理 |
| 商品_待分配 | 禁止出库 | 先分配笼位 | 保持原状态 |
| 已标记留种 | 排除出库 | 进入后备与单独饲养流程 | 不进入销售单 |
| 母兔生产周期 | 不作为商品出库对象 | 继续生产操作 | 保持生产状态 |
| 已出栏或不在场 | 不可选择 | 只读查看历史 | 保持终态 |

## 5.2 并行阻断维度

出库资格不能只看主状态。隔离、治疗中、未处理异常、笼位停用、权限不足、兔只不在目标兔舍、数据缺失以及并发变更均可影响资格。业务应为每种阻断定义稳定代码、严重级别、是否可处理和推荐动作。

| 分类 | 示例 | 处理口径 |
|-|-|-|
| 可确认 | 生长阶段提前出售 | 显式操作、原因必填、校验权限后纳入 |
| 需处理 | 未处理异常、资料缺失 | 定位业务页面处理，返回后重新预检 |
| 绝对阻断 | 已出栏、不在场、待分配、无权限 | 不可纳入本次出库 |
| 并发冲突 | 状态版本变化、已被其他任务处理 | 最终预检阻断，展示变化详情 |

# 6. 用户流程

1. **发起任务。**用户从单兔、笼位、排或兔舍入口进入，系统校验权限并创建或恢复草稿。
2. **范围展开与预检。**服务端返回候选兔只、空间坐标、资格分类、阻断原因、状态版本和默认选择建议。
3. **批量选择。**用户按排、按笼或整舍选择正常可出库兔，系统实时更新三级选择状态与汇总。
4. **逐兔处理。**用户下钻笼位，对单只兔移出、提前出售、标记留种或查看档案。
5. **冻结快照。**进入确认页时保存明确兔只 ID、状态版本、选择类型和提前出售原因。
6. **填写并核对。**用户填写日期、重量、客户、价格和备注，查看按排与笼位分组的兔只清单。
7. **最终预检与提交。**服务端重新校验状态、位置、权限和版本；全部通过后执行原子事务。
8. **结果反馈。**成功则展示销售单与汇总；冲突则保留草稿和表单，引导移除或处理具体对象。

# 8. 移动端交互要求

## 8.1 页面结构

选择页采用固定顶部导航、范围分段控制、状态摘要、可滚动空间列表和固定底部操作栏。确认页使用全屏页面，不在底部弹窗中堆叠完整表单。兔只列表使用可扩展底部抽屉，初始高度约占屏幕 70%，支持上拉至全屏。

## 8.2 交互约束

- 主要点击区域不小于 48 × 48 dp；常用操作放置于拇指易达区。
- 卡片主体负责查看详情，复选区域负责选择，两者不得混用。
- 关键操作不依赖长按、双击、左右滑动或纯手势。
- 所有选择状态同时使用图标、文字和数量，不只依赖颜色。
- 批量选择结果通过页面内数量即时反馈，避免频繁 Toast。
- 状态变化、自动移出和网络错误使用可解释的顶部消息条或问题卡片。
- 键盘弹出时当前字段、错误文案和后续操作保持可见。
- 系统字体放大至 200% 时双列卡片可切换单列，关键数字与按钮不截断。

## 8.3 关键文案

| 场景 | 推荐文案 |
|-|-|
| 整舍选择 | 选择整舍可出库兔 86 只 |
| 无已选对象 | 请选择兔只 |
| 进入确认 | 下一步 · 已选 86 只 |
| 最终提交 | 确认出库 86 只 |
| 长时间提交 | 正在确认提交结果，请勿重复操作 |
| 整单失败 | 本次出库未生效，草稿已保留 |
| 状态变化 | #214 已进入隔离状态，已从本次出库移除 |

| status | 选择中、待确认、提交中、已完成、已取消 |

每条销售明细至少保留兔只 ID、提交时笼位坐标、提交前主状态、并行状态摘要、是否提前出售、原因、单兔重量快照、生产批次 ID、操作者和提交时间。兔只后续换笼或档案修改不得破坏历史销售单的可追溯性。

# 10. 接口与服务约束

## 10.1 统一预检

预检接口接收兔舍与空间范围或明确兔只 ID，可选接收现有任务和已选兔只。返回完整范围汇总及逐兔结果，包括空间坐标、状态、资格分类、默认选择建议、阻断代码、原因文案、可执行动作和 stateVersion。核心资格由服务端判断，客户端只负责展示和维护草稿。

## 10.2 草稿接口

支持创建、读取、增量保存、取消和恢复任务。服务端草稿为跨设备和审计基线，本地缓存用于弱网与快速恢复；发生差异时不得静默覆盖，应以任务更新时间和状态给出明确恢复策略。

## 10.3 提交接口

```json
{
  "taskId": "task-id",
  "rabbitIds": [210, 211, 212],
  "stateVersions": {"210": 5, "211": 3, "212": 8},
  "earlySaleReasons": {"212": "客户提前采购"},
  "saleTime": "2026-07-29",
  "totalWeight": 86.5,
  "unitPrice": 18.0,
  "customer": "示例客户",
  "remark": "A排与B排集中出货",
  "requestId": "uuid"
}
```

服务端按 requestId 保证幂等。已成功的 requestId 再次请求应返回原销售单结果；正在处理时返回可查询状态；参数不一致地复用同一 requestId 应拒绝并记录异常。

## 10.4 事务边界

最终预检通过后在同一业务事务内创建销售单与明细、更新兔只状态和出栏历史、关闭活跃生产关系、更新批次状态与笼位在栏数量。任一步失败必须整体回滚，不向用户交付部分成功结果。提醒和报表如采用异步刷新，必须基于已提交事务的可靠事件，并能够重试与对账。

## 10.5 错误契约

错误应区分字段校验、资格阻断、版本冲突、权限不足、网络或系统错误。兔只级冲突返回 rabbitId、errorCode、currentState、message、recommendedAction；任务级错误返回是否可重试、原 requestId 状态和用户文案。不得只返回“提交失败”。

# 11. 异常与边界场景

| 场景 | 系统处理 | 用户反馈 |
|-|-|-|
| 范围内没有可出库兔 | 返回完整分类但默认选择为空 | 展示空状态并可查看需处理对象 |
| 兔只被其他人出库 | 最终预检判定已出栏或不在场 | 显示操作者与时间（如有权限），不得再次出库 |
| 兔只新增隔离或治疗状态 | 变为阻断并从选择移除 | 定位兔只并说明下一步 |
| 笼位停用或兔只换笼 | 重新校验位置和资格 | 显示原位置与当前位置，要求确认或移除 |
| 确认期间新兔进入范围 | 不加入冻结清单 | 无需打扰当前任务 |
| 网络中断但未提交 | 保存本地与服务端最近草稿 | 离线横幅，联网后重新预检 |
| 提交后网络中断 | 按 requestId 查询状态 | 显示提交状态未知，不允许创建重复请求 |
| 服务端部分写入失败 | 事务回滚 | 明确本次未生效，保留草稿 |
| 权限在任务中途被收回 | 最终预检拒绝提交 | 保留草稿，只读展示并联系管理员 |
| App 被杀死或升级 | 持久化任务标识和本地草稿版本 | 重新进入后提示恢复并执行预检 |
| 同兔只出现在多个未完成任务 | 允许草稿存在，提交时以最终状态和版本仲裁 | 冲突任务明确标记，不静默覆盖 |

# 12. 非功能需求

## 12.1 性能

- 选择操作在本地即时反馈，不等待全量网络往返；服务端预检结果异步校正。
- 长列表采用分组懒加载或虚拟列表，滚动过程中保持稳定帧率。
- 首屏应优先呈现任务标题、状态汇总、首个可操作分组和底部汇总。
- 关键接口需记录响应耗时并分范围规模统计；具体 SLA 在技术评审中确认。

## 12.2 可靠性与一致性

- 最终提交必须具备幂等、事务、状态版本校验和可查询结果。
- 任务成功后应有数据对账能力，识别销售单、明细、兔只、批次和笼位不一致。
- 异步提醒或报表更新失败不得回滚已成功销售，但必须可重试和监控。

## 12.3 安全与审计

- 所有接口按用户、兔场和动作校验权限，禁止只依赖客户端。
- 记录任务创建、选择快照、提前出售、留种、提交、冲突、成功和取消审计日志。
- 日志避免记录无必要的敏感客户信息；价格和客户信息遵循现有数据权限。

## 12.4 兼容性与无障碍

- 适配产品支持的 Android 最低版本、常见屏幕尺寸和系统导航模式。
- 支持系统字体放大至 200%，触控区域至少 48 dp，文本和背景满足可读对比度。
- 关键状态不得只使用颜色区分，读屏语义包含笼位、数量、选择和阻断状态。

# 18. 需求实现规格

本章节将前述需求进一步落到可以直接进入原型、客户端、服务端和测试实现的状态定义。页面不得只实现“正常有数据”一种形态；每个页面都必须覆盖初始化、加载、成功、空数据、局部失败、整页失败、离线、权限不足、状态冲突和提交恢复等状态，并明确可见组件、可用操作与状态迁移。

## 18.1 客户端状态分层

客户端状态分为任务域状态、页面状态、网络与同步状态、临时交互状态四层。四层可组合，但任务域状态是唯一业务事实；页面 loading、抽屉开关和 Toast 等不得反向替代任务状态。

| 层级 | 建议枚举或对象 | 职责 | 持久化 |
|-|-|-|-|
| 任务域状态 | selecting、confirming、submitting、completed、cancelled | 控制任务生命周期和允许动作 | 服务端持久化，本地缓存 |
| 页面加载状态 | initial、loading、ready、empty、partialError、fatalError | 控制骨架屏、内容、空态和错误页 | 不持久化 |
| 同步状态 | online、offline、saving、saved、saveFailed、stale | 控制草稿保存、离线横幅和重新预检 | 本地保存最近状态 |
| 提交状态 | idle、validating、requesting、unknown、success、conflict、failed | 防止重复提交并恢复未知结果 | requestId 必须持久化 |
| 临时交互状态 | selectionMode、filter、expandedRows、drawer、scrollOffset | 维持页面操作现场 | 会话内保存；关键返回现场可本地保存 |

## 18.2 推荐的页面 ViewState

以下结构用于约束状态完整性，不要求客户端逐字采用同名类。实现可使用 Riverpod、Bloc、Provider 或现有状态管理框架，但同一页面必须保持单一可信 ViewState，禁止列表、底栏和确认页各自维护独立已选数量。

```dart
enum LoadStatus { initial, loading, ready, empty, partialError, fatalError }
enum SyncStatus { online, offline, saving, saved, saveFailed, stale }
enum SelectionMode { cage, row, rabbitry }
enum Eligibility { normal, earlySale, needsAction, blocked }
enum CheckState { unchecked, checked, indeterminate, disabled }

class OutboundSelectionState {
  final String taskId;
  final String rabbitryId;
  final LoadStatus loadStatus;
  final SyncStatus syncStatus;
  final SelectionMode mode;
  final Eligibility? activeFilter;
  final List<RowGroupVm> rows;
  final Set<String> selectedRabbitIds;
  final Map<String, int> stateVersions;
  final Map<String, String> earlySaleReasons;
  final Set<String> expandedRowIds;
  final String? openedCageId;
  final String? bannerMessage;
  final String? errorCode;
  final bool isRefreshing;
  final bool hasUnsavedChanges;
}
```

派生数据统一由 selectedRabbitIds 和预检列表计算，包括 selectedRabbitCount、selectedCageCount、selectedRowCount、各排和各笼 CheckState、下一步按钮状态。不得在多个组件中用增减计数方式分别维护，以免取消选择、刷新和冲突移除后产生不一致。

## 18.3 任务状态迁移

| 当前状态 | 事件 | 前置条件 | 下一状态 | 副作用 |
|-|-|-|-|-|
| 无任务 | createTask | 具备创建权限 | 选择中 | 创建 taskId，执行范围预检 |
| 选择中 | continueToConfirm | 至少选择 1 只，草稿保存成功或可恢复 | 待确认 | 冻结 rabbitIds、版本和原因快照 |
| 待确认 | backToSelection | 未进入提交中 | 选择中 | 保留销售表单，允许更新选择 |
| 待确认 | submit | 表单通过、无阻断、在线、有权限 | 提交中 | 生成并持久化 requestId，发送提交 |
| 提交中 | submitSuccess | 服务端事务完成 | 已完成 | 保存 saleOrderId，清理可编辑草稿 |
| 提交中 | submitConflict | 最终预检冲突 | 待确认 | 保留表单与有效选择，记录冲突项 |
| 提交中 | resultUnknown | 超时或连接中断 | 提交中 | 进入 unknown 子状态，按 requestId 查询 |
| 选择中或待确认 | cancelTask | 用户二次确认 | 已取消 | 取消服务端草稿，清理本地编辑数据 |
| 任意可编辑态 | permissionRevoked | 权限重新校验失败 | 原状态只读 | 停止保存和提交，展示联系管理员 |

提交中不允许用户返回后创建新任务。App 重启后若存在未决 requestId，应优先进入提交恢复页查询结果；只有服务端明确返回“请求不存在且未提交”后，才允许恢复为待确认并重新生成 requestId。

## 18.4 批量选择页状态规格

| 状态 ID | 触发条件 | 界面表现 | 允许操作 | 退出条件 |
|-|-|-|-|-|
| SEL-INIT | 页面首次进入，尚未发起任务 | 保留页面结构；标题显示范围名称；内容区域为空 | 无 | 创建或恢复任务后进入 SEL-LOADING |
| SEL-LOADING | 创建任务或首次预检中 | 顶部和底栏保持稳定；状态摘要与首屏笼位使用骨架；主按钮禁用 | 返回；不允许选择 | 成功、空态或整页失败 |
| SEL-READY | 预检成功且存在候选对象 | 显示状态摘要、分组列表、三级选择和底栏汇总 | 筛选、选择、展开、打开抽屉、刷新、下一步 | 用户动作或刷新进入其他状态 |
| SEL-EMPTY | 范围内无任何在场商品兔 | 显示“当前范围没有可出库兔”，可展示范围名称和最近刷新时间 | 返回、刷新、查看兔舍 | 刷新获得数据 |
| SEL-NO-ELIGIBLE | 有兔但正常可出库和可提前出售均为 0 | 保留状态摘要，默认展示不可出库原因分组；下一步禁用 | 查看原因、处理异常、刷新 | 资格变化后进入 READY |
| SEL-PARTIAL-ERROR | 部分排或笼位加载失败 | 成功分组正常显示；失败分组显示内联重试，不使用整页错误 | 操作成功分组、重试失败分组 | 局部重试成功 |
| SEL-FATAL-ERROR | 任务或完整预检不可用 | 整页错误，说明原因；底栏隐藏或禁用 | 重试、返回 | 重试成功 |
| SEL-REFRESHING | 用户下拉刷新或业务编辑返回 | 保留旧列表与选择；顶部显示轻量刷新；受影响行可显示校验中 | 可查看；暂时锁定受影响对象的选择 | 合并新预检结果 |
| SEL-OFFLINE | 网络不可用 | 顶部离线横幅；展示缓存列表和本地选择；状态标记为可能过期 | 查看和本地编辑草稿 | 联网后自动进入刷新；不允许进入最终提交 |
| SEL-STALE | 草稿或预检超过有效期 | 横幅提示“状态可能已变化，请重新校验”；下一步禁用 | 重新校验、返回 | 预检成功 |
| SEL-NO-PERMISSION | 无编辑权限或权限被收回 | 页面只读，复选框禁用；说明当前仅可查看 | 查看详情、返回 | 权限恢复后刷新 |

## 18.5 选择控件状态计算

排和笼位的复选状态只针对“当前正常可批量选择”的兔只计算。提前出售、需处理和禁止出库对象不进入分母，避免笼内存在阻断兔时永远无法显示全选。

| 条件 | CheckState | 展示文案 | 点击行为 |
|-|-|-|-|
| normalEligibleCount = 0 | disabled | 无可批量选择兔 | 不改变选择；可点击主体查看原因 |
| selectedNormalCount = 0 | unchecked | 可选 N 只 | 选择全部正常可出库兔 |
| 0 < selectedNormalCount < normalEligibleCount | indeterminate | 已选 X/N | 默认补齐选择全部；取消全部应提供明确再次点击或菜单规则 |
| selectedNormalCount = normalEligibleCount | checked | 已选 N/N | 取消该范围内全部正常兔 |

筛选只改变可见列表，不改变选择集合。用户在“不可出库”筛选下看不到已选正常兔时，底部汇总仍显示全局已选数量，并显示“当前筛选不包含已选对象”的辅助说明。

所有异步事件需具备防乱序机制。预检请求至少携带客户端 requestSequence 或以最新 task revision 判断；较早请求晚于较新请求返回时不得覆盖新状态。对同一兔只的提前出售、留种和选择操作应串行化或在当前行加锁。

## 18.12 草稿保存与合并策略

选择变化采用本地立即写入并对服务端防抖保存，建议停止操作 500–1000 ms 后批量提交；进入后台、跳转确认页和退出页面时立即 flush。服务端草稿保存应携带 taskRevision，发生版本冲突时返回最新服务端版本和差异。

| 场景 | 合并规则 |
|-|-|
| 本地更新且服务端未变化 | 正常保存，taskRevision + 1 |
| 服务端任务已完成或取消 | 服务端状态优先，本地转只读，不得覆盖 |
| 服务端选择被其他设备修改 | 提示任务已在其他设备更新；重新预检后以明确选择确认，不静默集合并集 |
| 本地仅有临时 UI 状态变化 | 不写服务端，只保留会话或本地缓存 |
| 离线编辑后恢复网络 | 先读取服务端 taskRevision，再决定保存或进入冲突恢复 |

## 18.14 数据库与并发实现

提交时以 rabbitId 和 stateVersion 执行乐观并发校验；对选中兔只按稳定顺序加锁，降低多任务交叉导致的死锁。幂等记录应在业务事务中与销售单结果建立唯一关系，requestId 设置唯一索引。

| 表或实体 | 建议约束 |
|-|-|
| outbound_task | task_id 主键；status、revision、operator_id、rabbitry_id；更新时间索引 |
| outbound_task_item | task_id + rabbit_id 唯一；selection_type、state_version、reason、cage_snapshot |
| outbound_request | request_id 唯一；request_hash、status、sale_order_id、error_snapshot |
| sale_order_item | sale_order_id + rabbit_id 唯一，防止同单重复明细 |
| rabbit | state_version 每次影响资格的变化递增 |

同一 requestId 携带不同请求体时，通过 request_hash 检测并拒绝。事务开始后需再次读取并验证全部兔只；不能只信任预检快照。若跨批次更新，仍需在同一业务事务内完成，或由明确的一致性设计替代，不能默认拆成多个独立提交。

## 18.16 缓存刷新与数据同步

提交成功后，客户端以 saleOrderId 和受影响 rabbitIds 定向失效缓存：兔只详情、笼位在栏数、兔舍汇总、生产批次、首页出售提醒、销售列表和报表入口。刷新失败不能改变销售成功事实，页面显示“数据刷新中”并在后台重试。

服务端通过可靠事件发布 OutboundCompleted，消费者更新提醒和报表。事件至少包含 eventId、saleOrderId、taskId、rabbitryId、rabbitIds、batchIds、occurredAt。消费者按 eventId 幂等处理，并提供失败队列、重放和对账任务。

| UI-004 | 用户正在填写提前出售原因 | 保存失败 | 抽屉保持打开，原因文本不丢失，当前行显示重试 |
| UI-005 | 确认页表单完整且在线 | 用户点击确认出库 | 先持久化 requestId，再进入提交中，连续点击不产生第二请求 |
| UI-006 | 提交请求已到达服务端 | 客户端网络中断 | 进入状态未知并查询同一 requestId，不返回确认页重新提交 |
| UI-007 | 最终预检有2只状态冲突 | 服务端返回冲突 | 保留表单和其他选择，可一键移除2只后重新校验 |
| UI-008 | 销售事务成功 | 首页提醒刷新失败 | 结果页仍显示成功，并提示数据刷新中，后台重试 |
| UI-009 | App 在提交未知状态被杀死 | 用户重新打开 App | 优先恢复 requestId 查询页，直到获得最终结果 |
| UI-010 | 用户离线编辑草稿，服务端任务已在另一设备完成 | 网络恢复 | 服务端完成状态优先，本地转只读并跳转结果，不覆盖服务端 |
