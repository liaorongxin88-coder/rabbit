# 批次统计指标：交互设计

- 状态：方案设计中，待业务确认
- 核对日期：2026-09-02
- 适用范围：Flutter App、Admin
- 前置阅读：[交互验收规范](../../project/interaction-acceptance-spec.md)、`app/.rule`、`admin/DESIGN.md`

## 1. 落点

需求在「所需技术栈涉及」一栏写的是「可以把数据看板页面做成这个功能」。
数据看板（`app/lib/src/ui/dashboard/screens/overview.dart`）在 `831752f`
之后已经有兔舍与批次选择器，把 28 个指标堆进去是可行的。

但这套指标全部以单个批次为口径，跟数据看板现有的九个指标不是一回事：
后者是「这个兔舍现在有多少兔」，前者是「这一批从配种到出栏干得怎么样」。
两者放同一屏，用户要先意识到上半屏受批次筛选影响、下半屏不受影响。

因此主落点定在批次详情，数据看板保留入口：

| 位置 | 内容 |
| --- | --- |
| App 批次详情 `ui/batches/screens/detail.dart` | 完整 28 项，按生产阶段分组 |
| App 数据看板 `ui/dashboard/screens/overview.dart` | 选中具体批次时，在现有指标下方给一个入口跳批次详情 |
| Admin `pages/workspace-livestock-page.tsx` | 完整 28 项，替换现有四项摘要 |

现有的四项摘要（产崽窝数、产崽总数、活崽总数、断奶数量）不再单独存在，
它们本来就是新清单的子集。

## 2. 版面

### 2.1 分组

需求给的 16 个横排本身就是生产时间线的顺序，按这个顺序分八组，组名用现场词汇：

| 组 | 指标 |
| --- | --- |
| 配种 | 配种日期、受胎数量、受胎率、配种母兔/公兔比例 |
| 怀孕 | 怀孕数量、流产率 |
| 产崽 | 产崽窝数、产崽总数、平均窝产数、活崽总数、平均活崽率 |
| 选留 | 选留窝数、选留总数、选留活崽率、窝均选留 |
| 断奶 | 断奶数量、断奶均重、断奶成活率 |
| 出栏 | 出栏数量、出栏成活率、出栏总重、出栏均重 |
| 销售 | 总销售金额、销售单价（重量口径）、销售单价（只数口径） |
| 料肉比 | 全程料肉比、育肥期料肉比、出肉率 |

分组是必要的。28 个数值平铺成网格，用户找「断奶成活率」得靠扫，
而按阶段分组之后，找哪个数就是回忆那件事发生在生产流程的哪一段。

### 2.2 排布

需求逐行指定了哪两个并排、哪个独占一行。这个信息要保留：并排的两个多是
「绝对数 + 它对应的比率」，并排本身在表达关系。

窄屏和大字号下并排放不下，规则是降为一列并保持原顺序，不重新配对：

- App：默认两列；`textScaleFactor >= 1.3` 或宽度小于 360 时降为一列。
  这与数据看板 `_MetricGrid` 现有的降列阈值一致，不新造一套。
- Admin：`grid-cols-2 sm:grid-cols-4`，沿用现有 `batch-statistics.tsx` 的断点。

组与组之间用小标题分隔，不用卡片套卡片。`admin/DESIGN.md` 明确禁止卡片套卡片，
整块统计放在一张卡里，组标题是卡内的分节。

## 3. 数值的四种状态

现在的实现只有一种状态：数字。`BatchStatistics.fromJson` 的 `_integer`
拿到非 int 直接抛 `FormatException`，域模型里连 null 都表达不了。
28 个指标里大半是比率，必须先把状态说清楚。

| 状态 | 含义 | 显示 |
| --- | --- | --- |
| 有值 | 分子分母都有，算得出 | 数值 + 单位 |
| 为零 | 确实是 0，例如没有流产 | `0`，正常显示 |
| 分母为零 | 这一步还没发生，例如未出栏 | `暂无`，配一句说明何时会有 |
| 口径未定 | 后端还没确定算法，例如出肉率未录入 | `未录入`，可点进去录入 |

把「为零」和「分母为零」分开是这一节的重点。新建批次的出栏成活率显示 `0%`
会被读成「一只都没活」，而事实是还没出栏。这两件事在养殖上差得很远。

这要求接口返回分子分母而不是只返回比值，[design.md](design.md) §5 已记下。

## 4. 共享构件

App 端现在有两份各自内部的指标控件：`detail.dart` 的 `_MetricTile`（1342 行）
和 `overview.dart` 的 `_MetricCard`（804 行）。两者都只收 `int`，
渲染 `'$value'`，没有单位、没有空值路径。

28 个指标里有百分比、比值、千克、元、元每千克、个每窝六种单位，
再加上 §3 的四种状态，两份内部实现都改不动。提取一个共享指标控件到
`lib/src/ui/core/widgets/`，参数至少包含标签、数值、单位、状态和可选说明。

Admin 侧 `components/metric-card.tsx` 的 `MetricCard({title, value: number, icon})`
同样只收 `number`，需要同步扩展。

## 5. 口径要能被追问

八处口径存在差异或待定（见 [design.md](design.md) §4 与 §6）。
现场看到一个数字第一反应是「这怎么算的」，尤其是料肉比这种跨了饲料、
出栏、转后备三本账的指标。

每个指标带一个说明入口，点开显示当前口径的一句话定义和它的分子分母实际取值。
例如全程料肉比展开后是：

```text
全程料肉比 = 3.58
分子 饲料 48515 kg（母兔 12380 + 商品兔 36135）
分母 出栏总重 13543 kg
```

这样口径改了之后，现场能自己看出数字为什么变，不用回来问。
分摊口径未定之前（design.md §3.2 缺口一），料肉比要明确标注是按哪种分摊算的。

## 6. 七条性质的适用范围

统计面板是只读的，`docs/project/interaction-acceptance-spec.md`
七条性质里有四条不适用，按规范要求写明豁免理由。

| 性质 | 适用 | 说明 |
| --- | --- | --- |
| 1 失败看得见 | 适用 | 取数失败在面板内显示错误与重试，不用 SnackBar |
| 2 失败不毁输入 | 仅出肉率录入适用 | 面板其余部分无输入 |
| 3 重复提交只生效一次 | 仅出肉率录入适用 | 录入带 `requestId` |
| 4 批量前后都要交代 | 不适用 | 无批量操作 |
| 5 边界拦住且说得清 | 仅出肉率录入适用 | 百分比范围校验，提示要说出允许范围 |
| 6 断网有活路 | 适用 | 见下 |
| 7 窄屏大字号不塌 | 适用 | 见 §2.2 |

断网时面板保留上一次成功取到的数据并标注取数时间，不是清空后显示错误。
现场网络不稳是常态，一个带时间戳的旧数比一屏错误有用。

## 7. 待确认项

1. 数据看板是否也要能直接展开完整 28 项，还是只保留跳转入口。
2. 出肉率的录入权限。它是屠宰场给的参数，录入者可能不是场内人员。
3. 口径说明（§5）展开到什么程度。只给一句定义，还是连分子分母的实际取值一起给。
4. 批次未开始（无配种记录）时，整块面板是显示八组「暂无」还是折叠成一句提示。
5. 这套指标是否需要导出。附件《信达兔业繁殖计划》说明现场本来在用 Excel 记这些数，
   如果系统不导出，现场很可能继续手抄回 Excel。

## 8. 验收

- 用附件里一行真实数据造夹具，逐项比对，差异要能解释到具体口径。
- 新建批次（未配种）时每个比率显示「暂无」而不是 `0%`。
- 有配种无出栏的批次，配种组有值、出栏组「暂无」，两者同屏不冲突。
- 断网时面板显示上次数据与取数时间。
- 360×800、200% 字号下八组全部可读，无溢出无截断。
- Admin 桌面与窄屏各验一次，`pnpm --dir admin lint` 与 `build` 通过。
