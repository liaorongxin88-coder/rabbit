## 1. 状态的组成

兔只没有一个可以覆盖所有业务的单一状态。页面和业务判断需要同时读取以下维度：

| 维度 | 业务含义 | 当前事实来源 |
| --- | --- | --- |
| 类型 | 种母兔、种公兔、后备兔或商品兔 | `type + gender` |
| 在场状态 | 在栏或已离场 | `is_active` |
| 并行限制 | 隔离、治疗中、未处理异常 | 隔离、治疗和异常记录 |
| 生产阶段 | 母兔繁育阶段、商品兔生长阶段、种公兔可配状态 | 按兔只类型读取对应字段 |
| 待办 | 下一步要执行的业务动作及到期时间 | `work_tasks` |
| 批次关系 | 兔只在哪些批次中被追踪 | 批次标签和周期的 `batch_id` |

展示和判断时按以下顺序处理：

1. `is_active=false` 表示兔只已经离场，死亡、淘汰或出售原因从离场记录读取。离场状态优先于其它阶段。
2. 在栏兔若处于隔离、治疗中或存在未处理异常，应显示并行限制，不能用生产阶段覆盖这些提示。
3. 无并行限制时，再按兔只类型显示繁育阶段、生长阶段或后备成熟状态。
4. 待办表示下一步工作，不等同于兔只当前阶段。例如商品兔可处于育肥期，同时持有未来的待出售任务。
5. 批次是追踪和批量圈选维度，不应替代兔只自身状态。

影响出库资格或并发判断的兔只、隔离、治疗和异常写操作会更新 `state_version`。批量出库在最终提交时重新核对版本、笼位和实时资格，不能只依赖用户进入页面时看到的状态。

## 2. 兔只分类

| 业务分类 | 存储识别 | 主要状态 | 主要去向 |
| --- | --- | --- | --- |
| 种母兔 | `type=0, gender=0` | 统一繁育阶段 | 推进生产周期，或死亡、淘汰、出售离场 |
| 种公兔 | `type=0, gender=1` | 可配、休整，另记最近配种日期 | 参与体配，或离场 |
| 后备兔 | `type=1` | 后备、成熟待转种 | 成熟后按性别转为种母兔或种公兔 |
| 商品兔 | `type=2` | 幼兔、成长期、育肥期、成熟 | 正常出库、提前出售、留作后备或离场 |

类型是业务身份，不是阶段。商品兔转后备、后备转种会改变类型；催情、配种、摸胎等操作只改变母兔生产阶段，不改变兔只类型。

## 3. 种母兔生产状态

### 3.1 阶段词汇

| 存储值 | 业务名称 | 对应待办 |
| --- | --- | --- |
| `READY` | 准备 | 无，通常是周期切换时的短暂状态 |
| `AWAIT_ESTRUS` | 待催情 | 催情 |
| `AWAIT_MATING` | 待配种 | 配种 |
| `AWAIT_PALPATION` | 待摸胎 | 摸胎 |
| `AWAIT_PREPARTUM` | 待备产 | 备产 |
| `AWAIT_DELIVERY` | 待分娩，也称待接产 | 接产 |
| `AWAIT_WEANING` | 待分笼，也称哺乳中 | 分笼 |

`SUSPENDED` 和 `RETIRED` 是状态机中的非管线枚举。当前隔离和离场首先由并行限制与 `is_active` 表达，业务页面不能只看 `current_stage` 判断兔只是否可操作。

### 3.2 正常转换

| 当前阶段 | 操作或结果 | 业务结果 |
| --- | --- | --- |
| 待催情 | 完成催情 | 进入待配种，并按兔场设置生成配种待办 |
| 待配种 | 完成配种 | 进入待摸胎；体配必须选择在栏种公兔，人工授精可不关联具体公兔 |
| 待摸胎 | 怀孕 | 进入待备产 |
| 待摸胎 | 空怀 | 当前周期以空怀结束，自动创建一个不继承原批次的新周期并进入待催情 |
| 待摸胎 | 不确定 | 保持待摸胎，必须选择今天或未来的复查时间 |
| 待备产 | 完成备产 | 当天进入待分娩 |
| 待分娩 | 正常产仔 | 建立窝记录，进入待分笼，并按断奶设置生成待办 |
| 待分娩 | 分娩失败 | 当前周期以分娩失败结束，复旧后进入新的待催情周期 |
| 待分笼 | 记录断奶 | 当前周期以已断奶结束，并按断奶数量建立待分笼库存；此时不创建商品兔 |
| 待摸胎、待备产、待分娩 | 流产 | 当前周期以流产结束，复旧后进入新的待催情周期 |
| 任一等待阶段 | 推迟 | 阶段不变，只更新下次提醒时间 |
| 任一开放阶段 | 母兔离场 | 所有开放周期以已离场结束，待办取消 |

分娩失败必须填写详情并上传图片，三项仔数均为 0。流产必须填写详情、死胎数并上传图片。记录断奶时断奶只数不能为负数；填写公母数量时，两者之和必须等于断奶只数。

断奶后的实际入笼是独立库存动作。用户从兔舍笼位选择“场内生产”，再选择生产批次和待分笼记录；提交分配后才创建商品兔、占用笼位并扣减待分数量。父母兔档案关联默认为空，只有用户在分笼时明确选择后才写入；出生批次和生产周期始终保存。完整约定见[兔舍统一入笼与生产分笼](../cage-rabbit-intake/README.md)。

### 3.3 入轨和重叠周期

录入存量种母兔时可以直接从待催情、待配种、待摸胎、待备产、待分娩或待分笼开始，不要求重新走完整流程。不同入轨点需要补录不同事实：

| 入轨阶段 | 必须补录 |
| --- | --- |
| 待催情、待配种、待备产、待分娩 | 进入该阶段的日期 |
| 待摸胎 | 配种日期，种公兔可选 |
| 待分笼 | 分娩日期和活仔数 |

一只母兔同一时间最多有一个处于待催情至待分娩的管线周期。待分笼不占这条管线，因此允许上一窝仍在哺乳时开启下一轮配种。批次页面必须按 `batchId + motherRabbitId` 展示该批次内的周期，不能拿母兔全局当前阶段代替。

空怀、流产、分娩失败和分笼后的自动接续周期默认不继承旧批次。旧批次保留已经发生的周期、窝和操作记录，新周期由用户按需要重新打入批次。

## 4. 其它兔只状态

### 4.1 种公兔

种公兔可记录 `READY`（可配）或 `RESTING`（休整）。完成关联种公兔的配种操作后，系统更新其最近配种日期。当前配种校验要求公兔在栏、性别为公、类型为种兔。`READY/RESTING` 暂未参与服务端配种资格判断，见本文第 8 节。

### 4.2 后备兔

后备兔只使用 `RESERVE`（后备）阶段。直接录入后备兔或商品兔留种后，系统根据兔场的后备成熟天数生成成熟待办。

商品兔转后备兔时：

- 只接受在栏商品兔。
- 需要 `control` 权限。
- 兔只必须有原笼位，并迁入可用的后备兔单兔笼。
- 若仍有活跃批次标签，必须明确确认强制退出批次。
- 转换后关闭待出售任务，建立后备成熟记录和待办。

后备兔转种时必须已经到达成熟日期，存在待处理成熟记录，当前笼位启用且只养这一只兔。母兔转种后在原笼开启不带批次的待催情周期；公兔转种后进入可配状态。

### 4.3 商品兔

商品兔的生长阶段按进入生长轨道的日期和兔场设置每日计算：

```text
幼兔 JUVENILE -> 成长期 GROWING -> 育肥期 FATTENING -> 成熟 MATURE
```

商品兔适应期可设置为 2 至 3 天，生长期为 15 至 18 天，育肥期为 12 至 15 天。三段之和决定成熟和待出售日期。每日 00:05 的任务会推进在栏商品兔阶段。

商品兔进入出库流程前还要检查笼位、隔离、治疗和异常状态。当前资格服务还依赖最新活跃批次标签中的阶段与出售计划快照：

| 情况 | 出库分类 | 处理 |
| --- | --- | --- |
| 批次标签显示可出售、待出售，或标签上的出售日期已到，且无阻断 | 正常可出库 | 可被批量默认选中 |
| 批次标签显示适应期、成长期、育肥期，或出售日期尚未到，且无阻断 | 可提前出售 | 逐兔确认并填写原因 |
| 有未处理异常 | 需人工处理 | 处理异常后重新预检 |
| 已离场、非商品兔、无笼位、笼位停用、隔离、治疗中或标签阶段缺失 | 禁止出库 | 先处理对应业务问题 |

这意味着 `rabbits.growth_stage`、`SALE_READY` 待办与出库资格尚未完全收敛到同一事实源。无活跃批次标签的商品兔可能已经成熟且收到待出售任务，但仍被出库预检判定为阶段缺失。该差异列入第 8 节，不能由客户端自行放宽资格。

商品兔也可以转为后备兔。留种与出库是互斥去向，完成留种后不能继续进入本次销售单。

## 5. 通用操作

| 操作 | 适用对象 | 业务结果 |
| --- | --- | --- |
| 编辑档案 | 在栏兔只 | 修改品种、来源、体重等资料；种母兔阶段不能在档案中手改 |
| 换笼 | 在栏兔只 | 空笼迁入、商品兔合笼，或种兔与后备兔单兔笼对调 |
| 隔离 | 任意在栏兔 | 保持原生产阶段，同时增加出库阻断 |
| 解除隔离 | 已隔离且在栏兔 | 清除隔离阻断，生产阶段不自动推进 |
| 死亡、淘汰、出售离场 | 任意在栏兔 | 置为离场，扣减笼位数量，退出活跃批次并取消待办 |

商品兔笼允许同类合笼，容量默认 10 只；种兔和后备兔使用单兔笼。种兔或后备兔进入已占用的非商品兔笼时执行对调，不能与商品兔笼对调。

离场操作不可撤销。兔只仍有活跃批次标签时，需要明确确认强制退出；种母兔离场还会结清全部开放周期。

## 6. 批次的业务口径

批次的主要用途是圈选一组兔只做批量操作，并追踪母兔周期、窝、商品兔和出栏结果。当前实现仍保留批次状态和成员表，因此更准确的描述是“追踪标签加一层可结束的生命周期”，还不是完全无状态的纯标签。

### 6.1 批次状态

| 状态 | 当前含义 | 允许操作 |
| --- | --- | --- |
| 计划中 | 新建批次的默认状态，包括空批次 | 加兔、查看、执行生产操作、结束 |
| 进行中 | 历史数据和客户端兼容状态 | 与计划中相同，只要尚未完成即可编辑 |
| 已完成 | 批次已结束 | 只读，不可再加入兔只 |

当未完成批次已经没有活跃成员时，查询结果会给出“可结束”提示，但普通成员移除和批次内出售不会自动结束批次。

### 6.2 成员规则

- 可以先创建空批次，再陆续加入兔只。
- 可加入的对象是种母兔、后备母兔和商品兔。种公兔及后备公兔不能作为批次成员加入。
- 同一兔只可以带多个不同批次标签，但同一个批次不能重复加入同一兔只。
- 新加入的种母兔或后备母兔如果没有开放的管线周期，会在该批次开启待催情周期。
- 移除成员只解除批次标签，不会关闭生产周期，也不会改变兔只当前阶段。
- 商品兔作为 `fattening` 成员追踪养育和销售；母兔作为 `breeding` 成员追踪生产周期。

### 6.3 批次操作

| 操作 | 范围 | 结果语义 |
| --- | --- | --- |
| 新建批次 | 空批次或最多 5000 个初始兔只 ID | 整个请求成功或失败，支持 `requestId` 幂等 |
| 追加成员 | 一组兔只 | 校验兔只在场、类型和重复标签后一次提交 |
| 移除成员 | 单只兔 | 只退出标签，不结束周期 |
| 批量催情、配种等待办操作 | 明确待办列表，或按批次、待办类型、笼位筛选 | 每只独立事务，允许部分成功，结果逐只返回 |
| 接产、记录断奶 | 单只母兔 | 记录产仔和断奶事实，断奶后形成待分笼库存，不直接创建商品兔 |
| 生产分笼 | 一个待分笼记录和一个或多个目标笼位 | 按明确分配创建商品兔、占用笼位并扣减待分数量 |
| 安全出库 | 单兔、笼、排或整舍 | 最终提交全部成功或全部回滚，可跨批次生成一张销售单 |
| 结束批次 | 单个批次 | 关闭批次，不直接改变兔只自身状态 |

服务端批量生产待办单次最多处理 500 项。批量操作采用部分成功语义，失败项可单独重试；批量出库采用整单事务，任何兔只发生版本、笼位或资格冲突时，本次销售不产生部分结果。

### 6.4 结束批次

结束批次需要同时满足：

1. 该批次没有开放的生产周期。`force=true` 也不能绕过这条规则。
2. 没有活跃成员；若仍有活跃成员，必须明确强制结束。
3. 强制结束只批量退出剩余标签，不代替接产、分笼、流产、离场等生产处理。

结束后批次状态为已完成，不能再加入兔只。历史周期、窝、商品兔来源、操作时间线和出栏快照继续保留。

## 7. 权限、幂等和审计

- 查看兔只、批次、周期和待办需要当前兔场的 `view` 权限。
- 录入、编辑、换笼、生产操作、批次成员和离场通常需要 `edit` 权限及对应功能权限。
- 商品兔转后备和后备转种需要 `control` 权限。
- 所有写操作必须在当前 `X-House-Id` 范围内校验对象归属，不能跨兔场引用兔只、笼位、批次或公兔。
- 写请求使用 `requestId`。相同业务草稿失败重试时复用原 ID，业务对象或关键参数变化后生成新 ID。
- 类型转换、阶段变化、离场、批次关系和生产动作需要保留操作人、业务时间与历史记录。

## 8. 待确认的业务口径

以下事项在当前实现中存在差异。本文记录现状，不替业务方直接选定新规则：

| 项目 | 当前实现 | 需要确认 |
| --- | --- | --- |
| 批次自动结束 | 普通移除成员、商品兔转后备和批次内出售不会自动结束；统一批量出库在最后一个活跃成员退出后仍会自动把相关批次设为已完成 | 批次应始终由人结束，还是允许特定流程自动结束 |
| 批次状态 | 新批次创建为计划中，加入成员后不会自动改为进行中；客户端仍兼容进行中 | 计划中和进行中是否保留两个业务状态，以及转换时机 |
| 后备母兔入批次 | 加入批次和配种校验允许 `type=1` 的在栏母兔进入生产流程；独立转种流程则要求成熟日期已到 | 入批次是否等同于转种，还是必须先完成成熟转种 |
| 种公兔可配资格 | 服务端校验在栏、性别和种兔类型，但暂不校验可配/休整、隔离、治疗和异常 | 哪些并行状态必须阻断体配和人工授精的公兔关联 |
| 批量数量 | 服务端上限是 500；Flutter 和 Admin 的部分界面仍显示单次最多 1000 只母兔 | 统一按 500，或由客户端分块并对用户说明部分成功 |
| 商品兔成熟事实源 | 生长阶段和待出售任务已经按兔只维护，出库资格仍读取最新活跃批次标签的阶段与出售计划；无批次商品兔可能被判定为阶段缺失 | 出库资格应以兔只生长阶段和 `SALE_READY` 待办为准，还是继续要求商品兔必须有活跃批次标签 |
| 非管线阶段 | 状态机定义暂停和离场，但当前业务判断主要使用隔离字段及 `is_active` | 是否要把暂停、离场正式投影到 `current_stage`，或从业务词汇中移除 |

业务方确认后，需要同时更新本页、对应专题、后端规则、Flutter、Admin 和回归测试，不能只改展示文案。
