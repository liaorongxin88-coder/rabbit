# 附件验收样例与边界场景

## 1. 样例来源

附件：`research/feishu/信达兔业繁殖计划2501228.xlsx`

选用两张表中按舍号和出栏日期精确对应的记录：

- `繁殖总表` 第 25 行：1 舍，第 7 胎，出栏日期 2024-08-01。
- `料肉比统计` 第 3 行：1 舍，出栏日期 2024-08-01。

这两行适合验证已批准的口径差异。`繁殖总表` 把 600 只转后备兔及其 1,050 kg 重量并入出栏数量和出栏总重；系统的出栏指标只统计实际销售的 6,834 只和 13,095 kg，转后备重量仅进入两个料肉比的产出重量。

## 4. 边界场景

| 场景 | 预期 |
| --- | --- |
| 新建批次没有配种记录 | 配种日期为 `NOT_RECORDED`；计数和合计显示真实零值；所有分母为零的比率为 `NOT_APPLICABLE`。 |
| 同一母兔在同批次有两个确认怀孕周期 | 配种母兔数和怀孕数量都计 1 只；受胎率和流产率的分子、分母按 2 个独立 `cycle_id` 计算。 |
| 只有人工授精周期 | `male_rabbit_id` 为空不算缺失；实际参与公兔数为零，公母比例返回 `NOT_APPLICABLE` 和 `ZERO_DENOMINATOR`。 |
| 自然配种周期缺少公兔 | 公母比例返回 `DATA_MISSING` 和 `MISSING_NATURAL_MALE`，其他配种指标正常计算。 |
| 多个配种日期 | 返回最早、最晚日期、日期数和每日去重周期数，客户端显示范围并允许展开。 |
| `litters.batch_id` 为空 | 散养记录不进入任何批次。 |
| 混批销售 | 每个批次和未归批次组分别录入重量；各组重量之和等于订单总重量，金额之和等于订单总金额；未归批次组不进入批次统计。 |
| 金额舍入尾差 | 两个批次各分配 0.500 kg、统一单价 12.01 元/kg 时，订单总额为 12.01 元；两组初算均为 6.01 元，服务端按固定顺序把 -0.01 元尾差调整到第一组，最终为 6.00 元和 6.01 元。 |
| 历史销售有兔只批次快照但没有批次重量分配 | 可独立确认的出栏数量保持可用；重量、金额、单价和依赖它们的料肉比为 `DATA_MISSING`。 |
| 旧单兔销售且批次唯一 | 服务端在兔只退出批次前冻结归属，并把订单总重量自动写入该批次分配；统一单价存在时销售和料肉比来源完整。 |
| 兼容期旧销售缺少单价 | 原销售操作完成并记录 `LEGACY_SALE_PRICE_GAP`；出栏数量和重量可用，金额与两项销售单价返回 `DATA_MISSING` 和 `MISSING_SALE_UNIT_PRICE`。 |
| 关闭兼容后提交不完整旧销售 | 在事务开始前返回升级提示，销售订单、明细、兔只退出事件和缺口事件均不新增。 |
| 历史投喂缺少批次或阶段分配 | 其他指标正常返回；受影响的料肉比为 `DATA_MISSING`。 |
| 投喂单位不是 kg | 新分配请求返回 400；历史日志不会自动换算，相关料肉比返回 `DATA_MISSING` 和 `MISSING_FEED_UNIT`。 |
| 投喂预览后分组变化 | 保存时服务端重新解析候选组并拒绝过期分配，客户端刷新预览后保留总量输入。 |
| 断奶数量大于零但没有总重快照 | 断奶数量和断奶成活率正常返回；断奶均重及依赖断奶总重的育肥期料肉比为 `DATA_MISSING`。 |
| 转后备数量可确认但没有重量快照 | 出栏与销售指标不受影响；两个料肉比为 `DATA_MISSING`。 |
| 没有出栏且来源完整 | 出栏数量、重量和销售金额显示真实零值；均重、单价、成活率和料肉比因分母为零返回 `NOT_APPLICABLE`。 |
| 育肥增重恰好为零 | 育肥期料肉比返回 `NOT_APPLICABLE` 和 `ZERO_DENOMINATOR`。 |
| 育肥增重小于零 | 育肥期料肉比返回 `DATA_MISSING` 和 `INVALID_FATTENING_GAIN`，API、Admin、Flutter 和 Excel 都不得显示负料肉比。 |
| 未录入出肉率 | 出肉率为 `NOT_RECORDED`，其他 27 项不受影响。 |
| 统计刷新失败 | Admin 和 Flutter 保留上一次成功结果，显示更新失败和原取数时间，并提供局部重试。 |
| 只读人员查看批次 | 具备 `rabbit:batches:query` 即可查看统计；无 `rabbit:batches:edit` 时不显示出肉率录入操作；无 `rabbit:audit:list` 时不显示完整版本历史。 |
| 无报表导出权限 | Admin 和 Flutter 不显示 Excel 入口；直接请求导出端点由后端拒绝。 |
| 同一指标同时缺销售、饲料和转后备重量 | 返回全部 `missingCauses`，顺序固定为 `MISSING_BATCH_SALE_ALLOCATION`、`MISSING_FEED_ALLOCATION`、`MISSING_REPLACEMENT_WEIGHT`。 |

## 5. 可执行夹具结构

附件样例分为服务层原始聚合夹具和 MySQL 端到端夹具。两者共用本文件第 3 节的 28 项期望值，不能分别维护另一套数字。

### 5.1 服务层原始聚合

构造一个 `BatchStatisticsRawSnapshot` 等价对象，输入第 2 节的附件值和补充值。该测试直接验证指标目录、公式、状态、原因顺序、原始精度和 `displayValue`，不依赖 SQL 行数。

### 5.2 MySQL 数据分布

端到端夹具使用确定性序号生成数据：

- 生成 1,230 个配种周期、1,230 只去重母兔和 60 只去重公兔，配种日均为 2024-04-22。公兔按序号循环分配。
- 前 1,059 个周期标记为确认怀孕，前 21 个已怀孕周期各增加一个流产事件。
- 生成 1,004 窝，每窝 `total_kits = 10`，合计 10,040。
- 第 1 至 834 窝 `live_kits = 10`，第 835 至 1,004 窝 `live_kits = 9`，合计 9,870。
- 第 1 至 607 窝 `kept_kits = 10`，第 608 至 987 窝 `kept_kits = 9`，其余为 0，合计 9,490，选留窝数 987。
- 第 1 至 956 窝 `weaned_count = 9`、`weaning_total_weight_kg = 6.615`，其余为 0，合计断奶 8,604 只、6,323.940 kg。
- 生成一笔属于目标批次的销售，含 6,834 个有 `batch_id_snapshot` 的明细；批次分配为 13,095.000 kg、12.00 元/kg、157,140.00 元。
- 生成一笔转后备操作，目标批次 600 只、实测总重 1,050.000 kg。
- 生成投喂分配：`BREEDING = 22,050.00 kg`、`FATTENING = 30,070.00 kg`，合计 52,120.00 kg。
- 追加一条出肉率版本，原始值为 0.560000。

数据库夹具必须使用生产代码中的怀孕、流产和销售状态常量，不能在测试里另造中文状态值。

## 6. Excel 导出断言

使用第 3 节的同一份期望值生成工作簿，再由测试中的 OOXML 解析器重新打开：

- 页签顺序固定为 `批次统计`、`口径与状态`，不得出现第三个隐藏页签。
- `批次统计` 首行依次为兔舍、批次编号、统计时间和 28 个最终产品 `excelColumnName`，第二行对应一个批次；其中必须包含“配种母兔数”和“怀孕数量”，不得回退为附件的“配种数量”和“受胎数量”。
- 28 个 `AVAILABLE` 数值使用数值单元格及匹配的整数、小数或百分比格式；配种日期使用 ISO 日期或日期范围文本。
- `NOT_APPLICABLE`、`NOT_RECORDED`、`DATA_MISSING` 在结果页分别写入已确认的中文状态文本，不能写成 0。
- `口径与状态` 恰好有 28 个指标数据行，顺序和 `metric-catalog.md` 一致，并保留全部缺失原因机器码和中文说明。
- `CONCEPTION_RATE`、`FULL_FEED_CONVERSION_RATIO`、`CARCASS_YIELD_RATE` 分别断言原始值、展示值和 Excel 数字格式。
- 文件响应断言 OOXML MIME、UTF-8 `filename*`、ASCII 文件名回退、非空正文、兔舍隔离和 `rabbit:reports:export` 权限。
