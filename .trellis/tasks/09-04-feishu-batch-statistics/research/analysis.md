## 3. 当前系统能做到什么

### 已经实现

`GET /api/batches/{batchId}/statistics` 已按 `litters.batch_id` 返回四项：

- 产崽窝数：`count(litters.id)`
- 产崽总数：`sum(litters.total_kits)`
- 活崽总数：`sum(litters.live_kits)`
- 断奶数量：`sum(litters.weaned_count)`

证据：`backend/rabbit-production/src/main/resources/mapper/modules/batch/BatchStatisticsMapper.xml:6`、`backend/rabbit-production/src/main/java/com/rabbit/app/modules/batch/dto/BatchStatistics.java:3`。

### 有原始数据，可以扩展

- 配种日期、配种周期、配种母兔和公兔来自 `breeding_cycles`。
- 受胎结果由现役流程写入 `breeding_cycles.pregnancy_result`，`result` 是周期终态字段。旧设计中“二选一”的待确认项已经可以删除。
- 怀孕和流产可按 `repro_events` 的事件类型与 `cycle_id` 统计。
- 选留窝数、选留总数来自 `litters.kept_kits`。
- 断奶均重已有 `litters.avg_weaning_weight`，它在断奶操作时由用户录入，但 Flutter 将该字段标为可选，后端也没有非空或正数校验。若采用这个来源，批次断奶均重应按 `sum(weaned_count * avg_weaning_weight) / sum(weaned_count)` 加权，不能简单平均各窝均重。
- 出栏数量可读取 `sale_order_items.batch_id_snapshot`，但只覆盖写入该快照的批量出库路径。

### 缺数据或现有数据不够准确

1. 饲料没有批次分摊。`feed_logs.amount` 是兔舍级一单总量；关联表记录兔只和投喂时笼位，但没有单兔、单笼或单批次饲料量，也没有历史体重快照。当前 Flutter 投喂入口允许一次选择多个笼位，却只录入一个总用量。
2. 入笼原始总重没有持久化。`BatchRabbitEntryRequest.totalWeight` 只被除以数量后写成兔只当前体重，后续称重会覆盖它。
3. 销售重量和金额缺少批次级准确分摊。批量出库的订单总重量来自用户输入，订单总金额为 `totalWeight * unitPrice`；明细行 `weight` 却是兔只当前体重。一张订单混装多个批次时，直接汇总明细重量不一定等于过磅总重量，也无法可靠分摊订单总金额。
4. 旧销售路径不写 `batch_id_snapshot`、行重量和行单价，更旧的批次直售路径不创建销售明细。历史批次无法按现有字段完整回算。
5. 系统没有销售退单或冲正能力，统计无法定义退单后的净出栏和净收入。
6. 系统没有出肉率、屠宰重量或屠宰记录字段，必须新增录入与版本留痕。
7. 系统已有商品兔转后备兔操作，但 `replacement_records` 没有批次和转换时重量快照。通过 `rabbits.birth_batch_id` 只能有限回算数量，不能准确汇总转后备总重。

## 4. 主需求与附件的冲突

### 受胎数量名称不一致

主记录把“受胎数量”定义成“进行配种的母兔数量”，但附件分别有“配种数量”和“受胎数量”，并用 `受胎数量 / 配种数量` 计算受胎率。建议把主记录第 2 行改名为“配种母兔数”，保留“怀孕数量”表示确认受胎数。

### 育肥期料肉比分母不同

主记录：

```text
育肥期料肉比 = 育肥饲料量 / 出栏总重
```

附件“料肉比统计”表：

```text
断奶总重量 = 断奶数量 * 断奶均重
育肥增加重量 = 总出栏重量 - 断奶总重量
育肥期料肉比 = 育肥饲料量 / 育肥增加重量
```

附件实际公式为 `Q = P / O`。两种口径结果不同，不能混用。

### 全程料肉比分母不同

主记录只用出栏总重。附件先计算：

```text
总出栏重量 = 商品兔出栏重量 + 转后备兔重量
全程料肉比 = 全程饲料重量 / 总出栏重量
```

转后备兔也消耗本批次饲料。若分母不计入其重量，全程料肉比会偏高。

### 单位不一致

主记录把断奶均重写成 kg。附件“繁殖总表”使用 810、900、976 这类克值，“料肉比统计”则使用 0.810、0.900、0.976 kg。接口和界面必须统一单位。

### 附件独有指标

附件还包含产仔率、选留产仔率、精液贡献率、公斤造肉成本和商品料肉比。它们不在主记录 28 项中，不应默认纳入 MVP。

其中附件公式包括：

- 产仔率：产仔窝数 / 配种数量
- 选留产仔率：选留窝数 / 配种数量
- 窝均选留：选留数量 / 选留窝数
- 断奶成活率：断奶数量 / 选留数量
- 出栏成活率：出栏数量 / 断奶数量
- 出栏均重：出栏总重 / 出栏数量
- 精液贡献率：出栏数量 / 配种数量，名称与计算含义不直观
- 公斤造肉成本：饲料总费用 / 出栏总重量

## 5. 统计规则与建议

已确认主记录的 28 项是 MVP 范围，附件只用于核对算法和测试数据，附件独有指标不纳入本期。原“受胎数量”改名为“配种母兔数”。受胎率和流产率按 `cycle_id` 去重统计，配种母兔数、公母兔比例和怀孕数量按兔只去重，其中怀孕数量只统计至少有一个确认怀孕周期的母兔。育肥期料肉比以育肥增重为分母。全程料肉比分母包含商品兔实际出栏总重和转后备兔实测总重。投喂用量按批次和阶段精确归属，混批时分别录入，不做系统均摊。断奶操作保存总重快照，批次断奶均重按总重之和除以只数之和计算。出库按批次保存实际重量和金额快照，混批时分别录入，统一重量单价必填。缺少可靠快照的历史销售指标不回填，按单项返回 `DATA_MISSING`。出肉率由批次编辑权限人员录入，MVP 不设审核，修改时追加版本。配种日期按去重自然日统计，单日直接显示，多日显示起止范围并提供每日周期数明细。完整统计放在批次详情，看板保留概览和跳转入口。MVP 生成真实 `.xlsx`，Admin 和 Flutter 都提供入口；工作簿包含 `批次统计` 与 `口径与状态` 两个页签，并直接使用同次统计快照。附件独有指标明确忽略。最终展示规则如下：

1. 比率只有在分母大于 0 时计算。分母为 0 返回 `value = null` 和 `NOT_APPLICABLE`，界面显示“暂无可计算数据”；分母大于 0 且分子为 0 时以 `AVAILABLE` 显示真实零值。
2. 后端使用原始精度计算，仅在生成展示值时使用 `HALF_UP`。计数显示整数；重量统一为 kg；金额、重量单价、普通比值和料肉比显示两位小数；公母兔比例显示为 `x.xx:1`；百分比原始值范围为 0 至 1，界面显示两位百分比。
3. 应录未录返回 `NOT_RECORDED`，历史依据不完整返回 `DATA_MISSING`。聚合来源不完整时整项不显示部分合计。

## 6. 验收建议

- 用附件中的一行真实数据构造测试夹具，逐项对比；任何差异必须能指向已确认的口径差异。
- 新批次没有分母时，比率显示“暂无”，不能显示 `0%`。
- 同一母兔在同批次有两个繁殖周期时，两个周期分别进入受胎率和流产率，配种母兔数仍只计一只。
- 一张出库单混装多个批次时，各批次分摊重量和金额之和必须等于订单总重量和总金额。
- 散养记录的 `litters.batch_id` 为空时，不进入任何批次统计。
- 历史订单缺少快照或分摊字段时返回明确的数据状态，不用零值掩盖缺失。
- 每个比率类指标可查看分子、分母、统计范围和取数时间。
