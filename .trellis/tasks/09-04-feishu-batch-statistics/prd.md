# 飞书批次统计需求分析

## Goal

基于线上飞书主记录、附件台账和当前代码，规划并实现生产批次统计的 28 项 MVP 指标与 Excel 导出，使产品、现场和研发可以依据同一套口径查看、导出和验收批次数据。

## Background

- 主需求来自飞书多维表格「鸿兔项目开发 需求收集与管理」记录 `recvsV7QhkxxvD`，标题为“批次可以查看的统计数据及相关计算方式”。
- 线上状态为“方案设计中”，优先级为“中 - P1”，提出日期为 2026-08-21，负责人和完成时间未填写。
- 主记录列出 28 项指标，覆盖配种、怀孕、产崽、选留、断奶、出栏、销售、料肉比和出肉率，并附《信达兔业繁殖计划2501228.xlsx》。
- 详细证据、指标公式、附件差异和代码映射见 `research/analysis.md`。
- 当前接口 `GET /api/batches/{batchId}/statistics` 只返回产崽窝数、产崽总数、活崽总数和断奶数量。

## Confirmed Decisions

- D1. MVP 以飞书主记录的 28 项指标为唯一范围。
- D2. 附件只用于核对计算方式、单位和测试数据；附件独有的产仔率、选留产仔率、精液贡献率、公斤造肉成本和商品料肉比不纳入本期。
- D3. 本任务需要形成可执行的完整实现规划，覆盖后端统计契约、缺失数据采集、数据库迁移、Admin、Flutter 和自动化测试；规划经用户确认后再进入实现。
- D4. 飞书原“受胎数量”改名为“配种母兔数”，按去重母兔只数展示；“怀孕数量”使用 `PREGNANT_DOE_COUNT`，按确认怀孕周期中的 `mother_rabbit_id` 去重。界面和正式 Excel 表头都使用最终产品名称，附件旧列名只作为验收映射。
- D5. 受胎率和流产率按繁殖周期统计，分子与分母均按 `cycle_id` 去重；配种母兔数、怀孕数量和配种母兔/公兔比例按兔只去重。怀孕数量不作为受胎率的周期分子。
- D6. 育肥期料肉比按育肥增重计算，即育肥饲料量除以育肥增重；育肥增重等于纳入统计的出栏重量减去对应断奶总重。
- D7. 全程料肉比分母包含商品兔实际出栏总重和转后备兔实测总重；转后备操作必须保存 `batch_id` 和转换时的重量快照，不使用固定折算重量。
- D8. 投喂用量按“批次 + 阶段”精确归属。单一分组继续录入一个总量；多个批次或阶段分别录入用量并校验合计。未归属批次的用量不进入批次料肉比，不按兔只数量或当前体重自动均摊。
- D9. 断奶操作保存不可变的断奶总重快照。断奶数量大于零时总重必填且大于零；后端按总重除以只数派生窝均重。批次断奶均重和育肥增重直接使用断奶总重。
- D10. 出库按批次保存实际重量与金额分配快照。单一批次自动归属订单总重量；混批时分别录入每个批次及未归批次组的实际重量，分组之和必须等于订单总重量。重量单价必填，同一订单使用统一单价，批次金额按实际重量乘以单价计算。
- D11. 本期不对缺少可靠快照的历史销售数据做自动或人工回填。仅依据完整快照计算历史指标；缺少批次、重量或金额依据时返回 `DATA_MISSING` 并显示“历史数据缺失”，其他数据完整的指标不受影响。历史补录另立数据治理任务，并要求原始过磅单或销售单作为依据。
- D12. 出肉率由具备 `rabbit:batches:edit` 权限的人员在 Admin 或 Flutter 批次详情录入，MVP 不设二次审核，也不提供删除或作废。修改采用追加版本，最新版本进入统计；完整历史仅向具备 `rabbit:audit:list` 权限的人员开放。未录入时返回 `NOT_RECORDED`。
- D13. 配种日期按去重自然日展示。只有一个配种日时显示该日期；多个配种日时显示最早至最晚日期范围和配种日数量，并可展开查看每日去重 `cycle_id` 数量。没有配种记录时返回 `NOT_RECORDED`。
- D14. 完整 28 项统计只放在批次详情。Flutter 扩展现有批次详情，Admin 新增独立批次详情；数据看板保留现有概览，选中具体批次后提供“查看完整批次统计”入口，不移除现有看板指标。宽屏保留原需求指定的固定 16 行关系，包括第 14 行三个独立销售指标；窄屏和 200% 字号时按指标顺序逐项降为单列。
- D15. MVP 提供真实 `.xlsx` 文件生成和下载。导出使用同一份 28 项统计结果，保持固定编码、阶段、顺序、Excel 列名、单位、展示精度和数据状态；附件独有指标不进入导出，运行时不解析附件。
- D16. 计数显示整数；重量统一为 kg，金额、重量单价、普通比值和料肉比显示两位小数；公母兔比例显示为 `x.xx:1`；百分比接口使用 0 至 1 的原始值，界面显示两位百分比。后端以原始精度计算，仅在生成展示值时使用 `HALF_UP`。状态统一为 `AVAILABLE`、`NOT_APPLICABLE`、`NOT_RECORDED` 和 `DATA_MISSING`，聚合来源不完整或重量账不一致时整项不得显示部分合计。
- D17. 页面保持八组结构，出肉率放在“料肉比”组末尾，不新增“屠宰”第九组；接口阶段使用 `FEED_CONVERSION`。
- D18. Admin 和 Flutter 都在批次详情提供 Excel 导出。入口只对具备 `rabbit:reports:export` 权限的人员显示；Admin 下载文件，Flutter 使用带认证和 `X-House-Id` 的文件请求，并调起 Android 系统分享或保存。
- D19. Excel 包含 `批次统计` 和 `口径与状态` 两个页签。前者按固定顺序提供单批次 28 项横向结果，后者按指标逐行提供 code、公式、分子、分母、状态和缺失原因。
- D20. 新快照字段采用兼容过渡。后端先接受新旧载荷，旧载荷不伪造快照，受影响指标返回 `DATA_MISSING`。新版 Flutter 通过现有 `force_update` 能力强制升级；生产真机验证通过且连续 7 天没有旧载荷后关闭兼容开关。新版异常时重新开启开关并下架问题版本，保留追加数据库结构。

## Confirmed Facts

- 批次是单兔舍对象，当前模型不支持一个批次跨兔舍。
- 受胎结果由现役流程写入 `breeding_cycles.pregnancy_result`；`breeding_cycles.result` 表示周期终态，不再作为待决策项。
- 繁殖流程以 `cycle_id` 表达一次生产尝试；同一母兔可以在同一批次出现多个周期。人工授精周期允许 `male_rabbit_id` 为空，只有自然配种周期缺少公兔才属于数据缺失。
- `litters` 已保存产崽、活崽、选留、断奶数量和断奶时录入的窝均重，但 Flutter 将平均体重标为可选，后端只校验断奶只数，平均体重可能为空。
- 饲料记录没有批次级数量分摊，无法准确计算两个料肉比。当前 Flutter 投喂入口允许一次选择多个笼位，但整次操作只提交一个总用量并固定使用 kg；后端仍接受任意 `unit`。关联表虽保存兔只和当时笼位，仍无法把总量准确拆到多个批次。
- 入笼总重量没有不可变快照，兔只当前体重不能还原历史入笼总重。
- 批量出库保存订单过磅总重量，但明细行保存的是兔只当前体重；混批订单缺少批次级实际重量和金额分摊。
- 旧销售路径缺少批次快照、行重量和行单价，系统也没有销售退单或冲正能力。
- 系统没有出肉率或屠宰记录字段。
- 系统已有商品兔转后备兔操作，但转换记录没有批次和重量快照，只能有限回算数量，不能准确汇总转后备总重。
- 附件与主记录在育肥期料肉比分母、全程料肉比分母和断奶均重单位上存在冲突。
- 附件另有产仔率、选留产仔率、精液贡献率、公斤造肉成本和商品料肉比，主记录没有要求这些指标。

## Requirements

- R1. 统计范围必须绑定单个 `batchId` 和其所属 `houseId`，不按当前兔舍成员关系反推历史归属。
- R2. MVP 只包含飞书主记录的 28 项指标；附件独有指标不得进入接口或界面。
- R3. 每项指标必须定义业务名称、统计粒度、分子、分母、过滤条件、时间边界、单位、空值和舍入规则。
- R4. 受胎率按确认怀孕周期数除以已配种周期数计算，流产率按发生流产的已怀孕周期数除以确认怀孕周期数计算；两个比率均按 `cycle_id` 去重。配种母兔数、公母兔比例和怀孕数量按兔只去重，其中怀孕数量只统计至少有一个确认怀孕周期的母兔。
- R5. 比率分母为零时返回空值；真实零值只能表示分母有效且分子为零。
- R6. 出栏重量和销售金额必须按批次使用可核对的实际分摊值，不能直接以兔只当前体重代替过磅重量。
- R7. 育肥期料肉比按育肥饲料量除以育肥增重计算；全程料肉比的产出重量包含商品兔实际出栏总重和转后备兔实测总重。批次饲料分摊未完成时不得输出估算值；育肥增重等于零时返回 `NOT_APPLICABLE`，小于零时返回 `DATA_MISSING` 和 `INVALID_FATTENING_GAIN`。
- R8. 出肉率作为外部录入数据时，必须记录来源、录入人、录入时间和修改历史。
- R9. 历史数据无法回算时必须返回明确的数据状态，不得用零值代替缺失。
- R10. 每个指标应提供口径说明，并能查看比率的实际分子和分母。
- R11. 投喂保存批次和阶段分配明细，包括 `batch_id`、`phase` 和 `amount_kg`。新分配只接受 kg；单一候选且没有未归属对象时自动归属整单用量，多个分组由用户分别录入且分配合计必须等于整单总量。
- R12. 断奶记录保存 `weaning_total_weight_kg`。断奶数量大于零时该值必填且大于零；`avg_weaning_weight` 由后端计算并保留为兼容字段。
- R13. 出库保存订单批次分配明细，包括 `batch_id`、兔只数、实际重量、重量单价和金额快照。分组重量合计必须等于订单总重量；未归批次组计入订单但不进入任何批次统计。兔只当前体重仅供参考。现有 `/api/sales` 单兔路径在批次唯一时由服务端自动归属总重量；多批次或缺少单价的旧载荷按 R23 的兼容规则处理。
- R14. 历史统计只能使用可核验的不可变快照。缺少计算所需快照的指标返回 `DATA_MISSING` 及缺失原因，不得自动推算或阻断同一批次其他可用指标。
- R15. 出肉率记录必须绑定批次，数值大于 0% 且不超过 100%，并保存来源单位、检测或屠宰日期、录入人、录入时间和修改说明；报告编号、凭证图片和备注可选。修改时新增版本而非覆盖旧值。
- R16. 配种日期接口返回 `firstDate`、`lastDate`、`dateCount` 和按日期升序排列的每日去重周期数；前端不得把多日配种压成单个未说明的日期。
- R17. 批次详情按配种、怀孕、产崽、选留、断奶、出栏、销售和料肉比八组展示完整统计；宽屏按飞书原文保留固定 16 行关系，包括第 14 行三个独立销售指标；窄屏和 200% 字号时按原顺序逐项改为单列。每组支持查看口径、分子、分母、数据状态和缺失原因。看板只提供概览及批次详情入口。
- R18. 统计接口提供稳定、有序且可扁平化为 Excel 列的指标契约，包括 `code`、名称、阶段、顺序、Excel 列名、单位、原始值、格式化规则、分子、分母、状态和缺失原因。运行时不依赖或解析附件文件。
- R19. `AVAILABLE` 的真实零值必须正常显示；分母为零时返回空的 `numericValue` 或 `dateValue` 和 `NOT_APPLICABLE`，显示“暂无可计算数据”；应录未录返回 `NOT_RECORDED`，显示“未录入”；历史依据不完整或重量账不一致时返回 `DATA_MISSING` 和有序 `missingCauses`，显示“历史数据缺失”。
- R20. 后端根据查询时生成的同一份统计快照输出 `.xlsx`，不能让客户端重新计算指标。导出必须校验 `X-House-Id`、批次归属和导出权限，并返回正确的文件类型、UTF-8 文件名和 `Content-Disposition`。
- R21. Admin 和 Flutter 均提供导出入口。两端必须显示独立的下载中和失败状态，防止重复触发；导出失败不得清空或阻断批次详情中的统计结果。
- R22. `批次统计` 页以兔舍、批次编号和统计时间为前置列，后接固定 28 项指标；`口径与状态` 页按指标顺序逐行导出名称、code、阶段、单位、原始值、展示值、状态、公式、分子、分母、组成项和全部缺失原因。
- R23. 兼容模式由服务端配置控制并默认只用于过渡。每次旧载荷写入必须记录接口、客户端 build（未提供时为 `UNKNOWN`）、兔舍、requestId、发生时间和缺失快照类型；关闭兼容后，旧载荷返回明确的升级提示，不写入部分业务数据。连续 7 天零旧载荷按数据库业务本地时间的完整自然日计算，由发布负责人依据持久化操作事件查询结果执行切换。
